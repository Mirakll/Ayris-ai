# AYRIS — Техническое задание для Opus 5
Голосовой помощник для Windows 11. Название: **Ayris / Айрис**.
---
## 1. АРХИТЕКТУРА И СТЕК
### 1.1 GUI Framework
- **PySide6 (Qt 6)** — нативный, быстрый, низкое потребление памяти, отличная DPI-aware поддержка, стилизация через QSS.
- Альтернатива: **CustomTkinter** (если нужен более лёгкий вес), но PySide6 даёт лучший контроль над оверлеем, анимациями, системным треем.

### 1.2 Архитектура процессов (рекомендация)
**Гибрид: Основной процесс (GUI + ядро) + Изолированные воркеры для тяжёлых задач**
- Main process: GUI, координация, БД, настройки, плагины, макросы.
- Worker processes (multiprocessing + IPC через `multiprocessing.connection` или `ZeroMQ`):
  - Audio Capture + VAD + Wake Word
  - STT (Vosk / faster-whisper / Whisper.cpp)
  - TTS (Piper / Silero / Coqui)
  - LLM (llama.cpp / Ollama client)
- Преимущества: краш STT/TTS/LLM не уронит GUI, можно перезапускать воркеры, фоллбеки онлайн↔офлайн.

### 1.3 Хранение данных
| Данные | Формат | Путь |
|--------|--------|------|
| Настройки | `config.toml` | `%APPDATA%\Ayris\config.toml` |
| Команды, переменные, история, логи | `sqlite3` | `%APPDATA%\Ayris\ayris.db` |
| Модели (STT/TTS/Wake/LLM) | файлы | `%APPDATA%\Ayris\models\{stt,tts,wake,llm}\` |
| Плагины | Python пакеты | `%APPDATA%\Ayris\plugins\` |
| Портабельный профиль (экспорт) | `.zip` | пользователь выбирает |

### 1.4 Конфигурация
- `config.toml` — человекочитаемый, валидация через `pydantic-settings`.
- Горячая перезагрузка настроек без рестарта (кроме смены аудио-устройства/моделей).

## 2. РЕЖИМЫ РАБОТЫ МИКРОФОНА
| Режим | Описание |
|-------|----------|
| **Always Listening (Wake Word)** | Постоянно слушает, срабатывает на "Айрис" + варианты |
| **Push-to-Talk** | Активация по глобальному хоткею / кнопке в оверлее / кнопке на микрофоне |
| **Hybrid** | Переключение тумблером в UI и в оверлее |

**Wake Word:**
- Движки: `openWakeWord` (бесплатно, онлайн/офлайн), `Porcupine` (бесплатно для личного использования), `Vosk KWS`.
- Пользовательские варианты: неограниченный список, чувствительность (0.0–1.0) на каждый.
- Дедупликация (debounce) 1.5–2 сек после срабатывания.

## 3. STT (Speech-to-Text)
### 3.1 Онлайн (по умолчанию)
- Google Cloud Speech-to-Text
- Yandex SpeechKit
- Azure Speech Services
- OpenAI Whisper API

### 3.2 Офлайн (скачиваются в менеджере моделей)
- **Vosk** — малые модели (~50 МБ), быстро, CPU.
- **faster-whisper** — `tiny` (39 МБ), `base` (74 МБ), `small` (244 МБ), GPU (CUDA) ускорение.
- **Whisper.cpp** — альтернатива, отличная оптимизация CPU.

### 3.3 Переключение
- Тумблер в настройках и оверлее: **Online / Offline / Auto**.
- **Auto**: старт в Online, при потере интернета → автоматический фоллбек на Offline (если модели скачаны), уведомление в UI.
- Менеджер моделей: вкладка "Загрузка моделей", прогресс-бар, проверка SHA256, галочка "установлено", выбор активной модели.

## 4. TTS (Text-to-Speech)
### 4.1 Локальные (приоритет)
- **Piper** — быстрые, малые (~50 МБ/голос), много голосов, русские есть.
- **Silero** — хорошее качество, русские голоса, CPU.
- **Coqui XTTS v2** — клонирование голоса, требует GPU/больше RAM.

### 4.2 Облачные (опционально)
- ElevenLabs
- Yandex SpeechKit TTS
- Google Cloud TTS
- Azure TTS
- Coqui API

### 4.3 Настройки голоса
- Выбор движка → выбор голоса → скорость (0.5–2.0), тон, громкость.
- Загрузка своих моделей (Piper `.onnx`, Coqui `.pth`).
- Тест воспроизведения в настройках.

## 5. NLU / LLM / РАСПОЗНАВАНИЕ КОМАНД
### 5.1 Три режима (тумблер в настройках)
1. **Только ИИ (Q&A)** — всё уходит в LLM, ответ озвучивается.
2. **Гибрид** — сначала матчинг заготовленных команд (NLU), если не совпало → LLM.
3. **Только заготовленные команды** — LLM не используется, только NLU.

### 5.2 NLU для заготовленных команд
- **Matching**: точное совпадение, fuzzy (Levenshtein, порог настраиваемый), regex с именованными группами.
- **Слоты (named entities)**: `{app}`, `{time}`, `{volume}`, `{site}`, `{query}`, пользовательские типы.
- **Множественные триггеры** на команду, синонимы, приоритет (вес).
- **Контекст**: follow-up команды (после "открой браузер" — "закрой его"), активное окно, время суток, переменные.

### 5.3 LLM провайдеры

**Облачные:**
- OpenAI (GPT-4o, GPT-4o-mini)
- Anthropic (Claude 3.5 Sonnet, Haiku)
- OpenRouter (доступ к множеству моделей)
- YandexGPT
- GigaChat
- DeepSeek

**Локальные (через Ollama / LM Studio / llama.cpp):**
- Phi-3-mini (3.8B)
- Qwen2.5 (1.5B–7B)
- Llama-3.2 (1B–3B)
- Gemma 2 (2B–9B)
- Настройка: host/port Ollama, выбор модели из списка, системный промпт.

### 5.4 Промпты
- **Системный промпт для чата** (режим 1 и 2).
- **Системный промпт для NLU** (режим 2: "преобразуй речь в JSON команду из списка...").
- Длина контекста, история диалога (настраиваемая), суммаризация.

## 7. ДВИЖОК МАКРОСОВ (VOICEATTACK-STYLE)
### 7.1 Структура команды
- **Триггеры**: голосовая фраза (NLU), глобальный хоткей, системное событие (запуск приложения, таймер), таймер/расписание.
- **Действия (блоки)**: последовательный список с drag-and-drop / нодовый редактор.
- **Логика**: If/Else, Switch, While/For (с условием), Try/Catch, Call Command (подпрограммы), Return, Break/Continue.
- **Переменные**: строки, целые, дробные, булевы, массивы, словари. Область видимости: локальная (команда), профиль, глобальная. Персистентность (сохранение в БД).
- **Звуковое сопровождение**: привязка к этапам — на старте, на успехе, на ошибке. Источники: встроенная библиотека, генерация TTS, импорт `.wav/.mp3/.ogg`.
- **Состояние**: активна/неактивна, приоритет (перекрытие), кулдаун (мс/сек).

### 7.2 Базовые блоки действий
| Категория | Блоки |
|-----------|-------|
| **Голос/Звук** | Say (TTS), PlaySound, StopSound, SetVolume, SetTTSVoice |
| **Ввод** | KeyPress, KeyDown, KeyUp, TypeText, MouseClick, MouseMove, MouseDrag, MouseWheel |
| **Система** | RunApp, RunShell, CloseApp, FocusWindow, WindowState, SetBrightness, SetVolume, SetWifi, SetBluetooth, PowerAction, Screenshot, ClipboardSet, ClipboardGet |
| **Логика** | If, Else, Switch, While, For, Try, Catch, SetVar, GetVar, ArrayPush, ArrayGet, DictSet, DictGet |
| **Поток** | Wait (мс/сек/условие), CallCommand, Return, Break, Continue, Sleep |
| **Сеть/Веб** | WebRequest (GET/POST), OpenURL, SearchWeb |
| **Уведомления** | ToastNotify, OverlayLog |
| **Яндекс Музыка** | YMPlay, YMPause, YMNext, YMPrev, YMLike, YMSearch, YMPlaylist |

### 7.3 UI Редактора
- **Режимы**: Нодовый (visual scripting) + Список с параметрами (переключатель).
- **Отладка**: Step-by-step выполнение, breakpoint, watch переменных, лог выполнения с таймингами.
- **Hot reload**: изменение команды применяется сразу без рестарта.
- **История версий**: undo/redo в редакторе, экспорт версии.

### 7.4 Миграция
- Импорт VoiceAttack `.vap` (маппинг действий, переменных, звуков).
- Импорт AutoHotkey `.ahk` (базовый парсер: хоткеи, Run, Send, WinActivate).
- Экспорт в свой формат `.ayris` (JSON/YAML) с версионированием схемы.

## 8. ИНТЕРФЕЙС (UI)
### 8.1 Главное окно (Настройки)
**Вкладки:**
1. **Общие** — язык (только русский), тема, автозапуск, минимизация в трей, приоритет процесса, лимит RAM, пул потоков.
2. **Голос** — STT (движок, модель, онлайн/офлайн/авто, загрузчик), TTS (движок, голос, параметры, загрузчик), Wake Word (движок, варианты, чувствительность, добавление своих), Аудио вход (устройство, усиление, VAD порог, RNNoise шумоподавление).
3. **Команды** — библиотека команд (дерево категорий слева, редактор справа), импорт/экспорт, поиск, включение/выключение, приоритет, кулдаун.
4. **ИИ / LLM** — режим (3 тумблера), облачные провайдеры (API ключи, модели), локальные (Ollama/LM Studio, каталог моделей), системные промпты (чат + NLU), контекст/память.
5. **Горячие клавиши** — глобальные помощника (PTT, Wake toggle, Overlay, Mute), пользовательские для команд, детекция конфликтов, права админа.
6. **Оверлей** — настройки мини/расширенного режима, позиция, тема, анимации.
7. **Плагины** — список установленных, "+ Добавить кастомный плагин" (указание пути к Python пакету), маркетплейс (позже).
8. **Профили** — список профилей, создание/удаление/переключение, экспорт/импорт `.zip`, бэкап.
9. **Обновления** — автообновления (GitHub Releases), менеджер моделей (вкладка с предложенными моделями, кнопки скачивания, прогресс, галочки).
10. **Логи / DevTools** — уровень логов (DEBUG/INFO/ERROR), ротация, встроенная консоль REPL, текстовый ввод для теста команд, детальный лог пайплайна с таймингами.
11. **Приватность** — удаление истории, кэша, логов, отключение телеметрии (по умолчанию выкл).

### 8.2 Оверлей (Always on Top)
**Минимальный режим:**
- Маленькое красивое окно (капсула/круг) с анимированной **сферой из точек** по центру.
- **Анимации сферы**:
  - Idle: медленное вращение.
  - Listening: пульсация (расширение/сжатие).
  - Thinking: быстрые хаотичные движения точек / вращение.
  - Speaking: по краям окна белые волны от краёв к центру (до 2/3 пути).
  - Error: красная вспышка/дрожание.
- **Индикаторы (не кнопки, просто индикация)**:
  - Сверху справа: планетка — зачёркнута (офлайн) / не зачёркнута (онлайн).
  - Сверху справа: микрофон — зачёркнут (выкл) / не зачёркнут (вкл).
- **Переход в расширенный**: клик по панели "Ayris" слева сверху.
- **Тема**: тёмно-фиолетовая, футуристичная, минималистичная. Следует за системной или отдельная.
- **Поведение**: Topmost, опционально click-through, не перехватывает фокус, позиционирование (угол, центр, свободное перетаскивание, привязка к монитору), прозрачность, скрытие при бездействии.

**Расширенный режим:**
- Всё из минимального + лог диалога (услышано / ответ), кнопка микрофона, переключатель режима (Always/PTT), кнопки управления таймерами/напоминаниями, быстрый доступ к профилям, настройкам.

### 8.3 Системный трей
- Иконка с цветом статуса (зелёный/оранжевый/серый).
- Контекстное меню: Вкл/Выкл микрофон, Режим (Always/PTT), Оверлей (Мини/Расширен/Скрыть), Настройки, Профиль, Выход.
- Автозапуск с Windows (настройка в Общих), старт минимизированным в трей.

### 8.4 Библиотека команд (VoiceAttack-style)
- **Левая панель**: дерево категорий (папки), drag-and-drop перемещение команд.
- **Правая панель**: редактор выбранной команды.
- **Редактор команды**:
  - Имя, описание, теги.
  - Триггеры: список (голосовые фразы + regex, хоткеи, события, таймеры), добавление/удаление, приоритет.
  - Действия: нодовый редактор / список блоков (переключатель), параметры блока, drag-and-drop порядок.
  - Переменные: локальные/профильные/глобальные, типы, значения по умолчанию.
  - Звуки: вкладка "Звуки" — привязка к OnStart/OnSuccess/OnError, выбор из библиотеки / TTS / импорт.
  - Состояние: активна/неактивна, кулдаун, приоритет.
- **Поиск/фильтр** по имени, тегу, триггеру.
- **Импорт/экспорт** одной команды или папки в `.ayris`.

## 9. ПЛАГИНЫ / РАСШИРЯЕМОСТЬ
### 9.1 Архитектура
- Папка `%APPDATA%\Ayris\plugins\` — каждый плагин = Python пакет с `manifest.json`:
```json
{
  "name": "home_assistant",
  "version": "1.0.0",
  "entry_point": "plugin:HomeAssistantPlugin",
  "permissions": ["network", "settings_read", "commands_register"],
  "api_version": 1
}
```
- **Песочница**: плагины запускаются в отдельном процессе (опционально), ограниченные права, запрос разрешений при установке.

### 9.2 SDK (API для плагинов)
- `register_command(trigger, action)` — регистрация своей команды.
- `say(text)`, `play_sound(path)`, `notify(title, body)`.
- `get_setting(key)`, `set_setting(key, value)`.
- `execute_action(action_name, params)` — вызов встроенного действия.
- `on_event(event_name, callback)` — хуки: `on_startup`, `on_shutdown`, `on_command`, `on_wake_word`, `on_audio_level`, `on_timer`.
- `register_hotkey(combo, callback)`.
- `variables.get/set(scope, name, value)`.

### 9.3 Официальные плагины (планируемые)
- Home Assistant / MQTT
- Spotify / Яндекс Музыка (продвинутое)
- Discord (RPC, команды)
- Obsidian / Notion
- Steam (запуск игр, статус)
- Browser automation (Playwright-based)

### 9.4 Пользовательские плагины
- Кнопка "+ Добавить кастомный плагин" → выбор папки с `manifest.json` → валидация → установка.

## 11. БЕЗОПАСНОСТЬ И ПРИВАТНОСТЬ
- **Zero telemetry по умолчанию** — никакие данные не уходят без явного согласия.
- **Code Signing (EV сертификат)** — для устранения SmartScreen предупреждений (позже).
- **Песочница плагинов** — изоляция процессов, запрос разрешений (network, fs, admin, audio, input).
- **Опасные команды** (выключение, перезагрузка, удаление файлов, админ-действия) — требуют голосового подтверждения / ПИН / Windows Hello.
- **Разделение прав**: пользовательские команды vs админ-команды (манифест `require_admin: true`).
- **Аудит**: логирование всех выполненных команд с временем, параметрами, результатом.
- **GDPR-like**: кнопки в настройках — "Удалить историю команд", "Очистить кэш моделей", "Удалить логи", "Полный сброс профиля".

- Лимит RAM для локальных моделей: 2ГБ / 4ГБ / 8ГБ / Без лимита.
- Пул потоков: STT (1–4), TTS (1–2), LLM (1–2), Макросы (1–4).
- **Режим экономии**: при использовании онлайн STT/TTS/LLM — локальные воркеры не запускаются / приостанавливаются.
---
## 13. ИГРЫ / ПОЛНОЭКРАННЫЕ ПРИЛОЖЕНИЯ / UAC
- **Глобальные хоткеи в играх**: `interception` driver / Raw Input (требует админ-прав при установке, опционально).
- **Оверлей в играх**: не требуется (минимальный оверлей не перехватывает фокус, работает поверх через Topmost). Для полноэкранных exclusive — опционально D3D11 hook (позже).
- **UAC / Админ-права**: команды с `require_admin: true` запрашивают повышение через UAC prompt. Опция "Всегда запускать помощник от администратора" (не рекомендуется).
---
## 14. УСТОЙЧИВОСТЬ И ОБРАБОТКА ОШИБОК
- **Авто-перезапуск воркеров**: если STT/TTS/LLM воркер упал — перезапуск за 1 сек, уведомление в логе/оверлее, фоллбек на другой движок (онлайн→офлайн или наоборот).
- **Мониторинг устройств**: hot-plug микрофона/динамиков — детект, пауза/возобновление слушания, уведомление.
- **Устойчивость макросов**: Try/Catch вокруг каждого действия, лог ошибки, продолжение или остановка цепочки (настройка).
- **Валидация команд**: при сохранении — проверка ссылок на переменные, существование действий, циклов.

- **Локальные логи**: `%APPDATA%\Ayris\logs\ayris_YYYYMMDD.log`, ротация по размеру (10 МБ) и дате (7 дней).
- **Уровни**: DEBUG / INFO / WARNING / ERROR (настройка в DevTools).

```yaml
name: "Рабочий режим"
triggers:
  - voice: "айрис рабочий режим"
    priority: 50
  - hotkey: "ctrl+alt+w"
actions:
  - type: SetVar
    params:
      name: "work_mode"
      value: true
      scope: "global"
  - type: RunApp
    params:
      path: "code"
      args: ""
  - type: RunApp
    params:
      path: "chrome"
      args: "--profile-directory=Work"
  - type: If
    params:
      condition: "{work_monitor_brightness} > 0"
    then:
      - type: SetBrightness
        params:
          monitor: "external_1"
          level: "{work_monitor_brightness}"
    else: []
  - type: Say
    params:
      text: "Рабочий режим активирован. Хорошего кода!"
      stage: "on_success"
  - type: PlaySound
    params:
      sound: "custom:work_mode_start.wav"
      stage: "on_success"
variables:
  work_monitor_brightness:
    type: "int"
    default: 70
    scope: "profile"
```
