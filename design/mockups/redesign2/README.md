# Obsidian 2c — рабочий мокап Ayris

Текущая версия для продолжения — **`2c-obsidian-chat.html`**.
Предпросмотр: <http://127.0.0.1:8779/redesign2/2c-obsidian-chat.html>.

Подготовлено 28.10.2026 с сохранением исходного вида в бэкапе. 29.10.2026
обновлена главная: убраны центральный AYRIS, слоган и эквалайзер.
Над опущенными кнопками — увеличенный икосаэдр из приложения, под ними —
AYRIS ASSISTANT. Размер икосаэдра регулируется селектором `#hero-icosa`:
480 px, при высоте окна до 720 px — 350 px. Свечение плавно исчезает до края
canvas, чтобы не проявлялась квадратная граница на фоне.
При открытии чата тот же аватар за 0.9 с увеличивается в 1.8 раза и остаётся
приглушённым фоном. Возврат плавно восстанавливает исходный размер; iframe
не пересоздаётся, вращение продолжается. При уменьшении движения в настройках
системы переходы и вращение отключаются.
Прежние варианты остаются в этой папке для сравнения. Сборка не требует npm
и новых пакетов.

## Где редактировать

| Часть | Источник |
| --- | --- |
| Палитра, шрифты, размеры, состояния, CSS | `2c-obsidian-chat.html`, блок `<style>` и `:root` |
| Главная, навигация, чат, история, фон и обработчики | `2c-obsidian-chat.html` |
| Страница «Общие» (`sp-general`) | `2c-obsidian-chat.html` — партиала пока нет |
| Голос, Команды, ИИ / LLM, Хоткеи, Оверлей, Профили, Обновления, DevTools, Приватность | Соответствующий файл `_sections/*.html` |
| Икосаэдр главной | `_icosa-app.html` — копия `src/ayris/gui/widgets/sphere/assets/icosa.html`: локальные пути importmap на `../redesign/sphere/vendor/` и плавное затухание альфы до края canvas |
| Прежний прототип икосаэдра | `_icosa.html` |
| Предпросмотр старой сферы | `../home/_sphere.html` |
| Сборка настроек | `_sections/_assemble.py` |
| Каталог вариантов | `index.html` |

Девять страниц настроек в целевом HTML — результат сборки партиалов.
Правки этих страниц вносить в `_sections`, иначе следующая сборка заменит их.
Оболочку, общие CSS/JS и «Общие» сборщик не генерирует.

Партиалы исторически общие с 2b. **По умолчанию сборщик обновляет только 2c**;
2b остаётся сохранённым HTML и меняется лишь при явном `--target`.
Проверка 2b после будущих изменений общих партиалов может показать расхождение —
это не повод автоматически обновлять прежний вариант.

## Сборка и предпросмотр

PowerShell, из корня проекта:

```powershell
$env:PYTHONIOENCODING = 'utf-8'

# Проверить совпадение партиалов с 2c, ничего не записывая.
& '_tools/venv/Scripts/python.exe' 'design/mockups/redesign2/_sections/_assemble.py' --check

# После изменения партиалов собрать 2c.
& '_tools/venv/Scripts/python.exe' 'design/mockups/redesign2/_sections/_assemble.py'
```

После изменения оболочки или сборки обновить страницу браузера. Сборщик не
перезаписывает файл при совпадении содержимого; сохраняет переводы строк и
учитывает вложенные `<section>`. Отсутствующий/пустой партиал, повторный ID
целевой секции или незакрытая секция останавливают сборку до записи.
Коды возврата: `0` — совпадает/собрано, `1` — `--check` обнаружил расхождение,
`2` — ошибка входных файлов или аргументов.

При необходимости работы именно со старой версией:

```powershell
& '_tools/venv/Scripts/python.exe' 'design/mockups/redesign2/_sections/_assemble.py' --target 2b-obsidian-violet.html --check
```

Сервер на 8779 уже работает на момент подготовки. Повторный экземпляр не нужен.
Если он остановлен, открыть `../run_redesign2.bat` либо запустить вручную:

```powershell
& '_tools/venv/Scripts/python.exe' 'design/mockups/_serve_nocache.py' 8779 design/mockups
```

Сервер привязан к `127.0.0.1` и отдаёт `no-store`. Предпросмотр вести по HTTP,
чтобы ES-модули и iframe загружались штатно.

## Следующая работа

Основание — [визуальный разбор 28.10.2026](../../../.ai/reviews/2026-10-28-obsidian/REVIEW.md).
Приоритеты ниже — рекомендации для следующего согласованного изменения.
В рамках подготовки они не реализованы.

1. Исправить перекрытие сообщений и поля ввода панелью истории.
2. Довести сценарий «главная → чат → история → настройки → возврат».
3. Проработать состояния: ожидание, прослушивание, ответ, шаг действия, ошибка,
   офлайн. В чате сохранить понятную индикацию профиля и состояния.
4. Успокоить фон за текстом, проверить вторичные подписи и уменьшить высоту
   верхней части страницы команд.
5. Проверить обычное и узкое настольное окно, длинные сообщения, прокрутку,
   клавиатурный фокус и уменьшение анимации.

После изменений проверять не только главную, но и наполненный чат с открытой
историей, все десять страниц настроек и оба предпросмотра сферы. Проверять
консоль браузера и загрузку ресурсов. Для изменений кода проекта общий прогон —
`bash scripts/check.sh`; он не заменяет визуальную проверку HTML-мокапа.

## Граница демонстрации

Ответ чата фиксированный; история выделяет строку, но не загружает беседу;
скрепка не подключена; нагрузка случайная, плеер имитирует время. Кнопка «Модель»
пока открывает раздел обновлений. Это элементы прототипа, не готовые функции
приложения. Сначала уточнить сценарии, затем подключать реальные данные.

Приложение остаётся на PySide6/QSS/QWebEngineView. При будущем переносе
сохранить существующие привязки настроек, общий поиск, события ответов и ошибок
независимо от TTS и шаги агента. Перенос в приложение — отдельная задача.
