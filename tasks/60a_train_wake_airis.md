# Задача 60a — Обучение слова активации «Айрис» (openWakeWord)

**Этап:** G — Интерфейс | **Связана с:** 60 (даёт `айрис.onnx` для гибридного дефолта) | **Разделы ТЗ:** 10

## Цель
Обучить пользовательскую модель слова активации `айрис.onnx` для openWakeWord и довести её **автономным циклом** до целевых критериев, затем положить готовый файл в `resources/models/wake/` и добавить запись в каталог `resources/models/wake.json`. После этого «Айрис из коробки» (задача 60, п. 13) работает на дефолтном движке openWakeWord без ручного обучения пользователем.

Обучение — **внешний по отношению к приложению шаг**: оно не запускается из Ayris и не входит в его зависимости. Артефакт — единственный `.onnx` (плюс, при желании, `.tflite`), который приложение лишь подхватывает.

## Что эта задача НЕ трогает (важно не спутать)
Обучается **только слово активации (wake)** для движка openWakeWord — ступень, которая ловит «Айрис» и будит ассистента. Это не распознавание речи.

- **STT/GigaAM не меняется.** Распознавание команды после пробуждения — отдельная ступень и отдельная модель; дефолт остаётся GigaAM (`config.py`, `offline_engine="gigaam"`). `айрис.onnx` её не заменяет и не конфликтует с ней. Конвейер: **Wake (openWakeWord/Vosk) ловит «Айрис» → STT (GigaAM) распознаёт саму команду.**
- **Выбор моделей пользователем не ограничивается.** Любые STT/TTS/LLM/wake-модели пользователь качает и переключает через менеджер моделей (задача 50). Обучение `айрис.onnx` нужно ровно для одного — чтобы **дефолтное** слово «Айрис» работало из коробки на чистой установке.
- **Другое слово активации не требует обучения под пользователя.** Если пользователь захочет не «Айрис», а своё слово — для этого в гибриде есть Vosk KWS, принимающий любое слово без обучения. Обучать модель под каждого пользователя не нужно.

## Целевые критерии (мягкие)
Модель считается готовой, когда на held-out валидации при рекомендованном пороге:
- **recall ≥ 90%** — из 100 чётких произнесений «Айрис» ловится не меньше 90;
- **≤ 2 ложных срабатывания в час** на негативном наборе (чужая речь + фоновый шум + музыка), суммарно ≥ 2 часов аудио.
Порог, на котором это достигнуто, записать в отчёт — он станет дефолтной чувствительностью варианта «айрис».

## Железо и окружение (проверено)
- GPU: **NVIDIA RTX 2060, 6 ГБ VRAM** — достаточно; обучается лёгкая голова поверх общих эмбеддингов.
- Диск: рабочая папка и venv — **на ASCII-пути**, `D:\ayris-wake-train\` (265 ГБ свободно). НЕ в репозитории на `E:\мистер бит ест рис\` — кириллица в пути ломает нативные аудио-либы (см. память проекта).
- Python: системный 3.14 **не подходит** (нет колёс torch/openwakeword). Создать отдельный venv **Python 3.11** с CUDA-сборкой torch.
- Сеть домашняя нестабильна — все загрузки датасетов/зависимостей делать с ретраями и докачкой; крупные наборы (негативные фичи, RIR/шум) тянуть на D:.

## Что сделать
1. **Окружение** (`D:\ayris-wake-train\setup.ps1`): venv на Python 3.11, установка `torch` (CUDA cu12x), `openwakeword`, `piper-sample-generator` и зависимостей обучения. Пины версий зафиксировать в `requirements-train.txt`. Проверка `torch.cuda.is_available()` перед стартом.
2. **Позитивы** (`01_generate_positives.py`): синтез многих тысяч клипов «Айрис»/«айрис» через `piper-sample-generator` — разные голоса, темп, высота, длительности; часть — с русскими вариациями произношения («аирис», «ирис»). Разбить на train/val.
3. **Негативы и фон**: скачать/подключить негативный набор фич openWakeWord и наборы шума/RIR (речь без слова, музыка, бытовой шум) для аугментации и для валидации ложных срабатываний. Держать отдельный held-out негативный набор ≥ 2 ч, не участвующий в обучении.
4. **Обучение** (`02_train.py`): следовать официальному пайплайну openWakeWord (`automatic_model_training.ipynb` / `openwakeword.train`) — обучить классификатор поверх общих `melspectrogram`+`embedding`, экспорт в ONNX. Параметры (объём позитивов, аугментация, эпохи) берутся из `config.yaml` и наращиваются циклом.
5. **Оценка** (`03_evaluate.py`): на held-out позитивах и негативах построить кривую recall / ложные-в-час по порогу, выбрать порог под целевые критерии, выдать вердикт «сошлось / не сошлось» и отчёт (JSON + короткий текст).
6. **Автоцикл** (`autoloop.py`): раунд = генерация/добор данных → обучение → оценка. Если критерии не достигнуты — наращивать объём позитивов, усиливать аугментацию, добавлять эпохи и трудные негативы (hard-negative mining из ложных срабатываний прошлого раунда) и повторять. Стоп по достижении критериев или по лимиту раундов/времени. Каждый раунд логировать метрики, чтобы виден был прогресс.
7. **Экспорт и установка** (`04_export_install.py`): взять лучший чекпойнт, экспортировать `айрис.onnx`, посчитать SHA256 и размер, скопировать в `resources/models/wake/`, вывести готовую запись каталога для `resources/models/wake.json` (kind=wake, language=ru, engine=openwakeword) и рекомендованный порог/чувствительность.
8. **Интеграция с задачей 60**: добавить запись `айрис.onnx` в `wake.json` и в «минимальный набор» онбординга; убедиться, что общие части (`oww-melspectrogram`, `oww-embedding`) там уже есть и качаются вместе. Проверить, что на чистом профиле с этими тремя файлами openWakeWord реально срабатывает на «айрис».

## Осторожно
- Обучение идёт вне приложения и вне CI: код/тесты Ayris **не должны** зависеть от наличия `.onnx` — только корректно подхватывать его.
- «Айрис»/«ирис» — короткое слово: склонно к ложным срабатываниям. Мягкие критерии выбраны осознанно; при недостижимости строгих цифр не гнать бесконечный цикл — упереться в лимит раундов и отдать лучший результат с честным отчётом.
- Все тяжёлые загрузки — с ретраями; при обрыве сети раунд должен продолжаться с докачки, а не начинать заново.
- Порог/чувствительность из отчёта переносить в дефолт варианта «айрис», а не оставлять 0.5 вслепую.
- Проверка живым голосом (реально ли ловит «Айрис» и не срабатывает на болтовню) — **руками**, автометрики этого не заменяют.
