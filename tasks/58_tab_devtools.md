# Задача 58 — Вкладка Логи / DevTools

**Этап:** G — Интерфейс | **Зависит от:** 43, 41, 18 | **Разделы ТЗ:** 8.1 (вкладка 10), 15

## Цель
Инструменты диагностики в одной вкладке: живой лог с фильтрами, таблица стадий пайплайна с таймингами, текстовый ввод команд, консоль REPL и панель здоровья воркеров.

## Что сделать
1. `gui/tabs/devtools.py` + `gui/widgets/log_view.py` — просмотр лога в реальном времени по событиям `LogLine` задачи 41 (не чтением файла): фильтр по уровню и по модулю, поиск с подсветкой и переходом по совпадениям, автопрокрутка с автоотключением при ручном скролле, цвет строки по уровню из токенов темы, копирование выделенных строк, пауза потока. Первичное наполнение из кольцевого буфера задачи 41, ограничение числа строк в виджете с вытеснением старых.
2. Переключение уровня логирования на лету (общего и для отдельного модуля) прямо из вкладки, кнопки «Открыть папку логов» и «Экспорт лога для баг-репорта» через `utils/bug_report.py` задачи 41 — с показом состава архива и напоминанием, что отправка ручная, ничего не уходит автоматически.
3. Панель пайплайна (`gui/widgets/pipeline_view.py`): таблица сессий по трейсам задачи 18 — время, `request_id`, `STT raw`, распознанный intent и слоты, выполненное действие, результат, суммарная длительность; раскрытие строки в стадии с длительностью каждой в мс и диаграммой-полоской для наглядности. Фильтр по результату (успех / не найдено / ошибка), выделение стадии, занявшей больше всего времени, переход к соответствующим строкам лога по `request_id`.
4. Поле текстового ввода: текст уходит в `Pipeline.run_text()` задачи 18 и проходит весь путь как голосовая команда, история введённых строк со стрелками вверх/вниз, результат и трассировка появляются в панели пайплайна, кнопка «Повторить последнюю». Тумблер «сухой прогон» (только распознавание, без выполнения действия).
5. Консоль REPL (`gui/widgets/repl_console.py`): выполнение Python в контексте приложения с доступом к app, конфигу, БД, реестру действий и движку макросов; вывод результата и трассировки исключений, автодополнение по `dir()` текущего объекта, история команд с сохранением между запусками, многострочный ввод, прерывание длительного выполнения. Выполнение вне UI-потока, чтобы упавший или зависший код не заморозил окно.
6. Предупреждение об опасности REPL: панель скрыта за явным подтверждением «Понимаю риски» при первом открытии (флаг в конфиге), пояснение, что код исполняется с правами приложения и может повредить данные; всё введённое пишется в аудит задачи 41.
7. Панель здоровья воркеров (`gui/widgets/worker_health.py`) по данным `WorkerManager` задачи 05: тип воркера, статус (работает / пауза / перезапускается / упал), аптайм, число перезапусков, потребление RAM, время последнего heartbeat, кнопки «Перезапустить» и «Пауза». Подсветка воркера, перезапускавшегося неоднократно.
8. Тесты без запуска окна: фильтрация и поиск в модели лога, вытеснение строк при переполнении, сборка таблицы стадий из трейса с корректными таймингами и суммой, `run_text` через поле ввода даёт результат в панели пайплайна, REPL выполняет выражение и возвращает трассировку при ошибке, модель здоровья воркеров отражает статусы и перезапуски.

`src/ayris/gui/tabs/devtools.py`, `src/ayris/gui/widgets/log_view.py`, `pipeline_view.py`, `repl_console.py`, `worker_health.py`, `tests/unit/test_devtools.py`

## Осторожно
- Живой лог на DEBUG — это тысячи строк в минуту: обновлять виджет пачками по таймеру, а не по каждой строке, иначе UI-поток встанет.
- В логах и трейсах могут быть чувствительные значения: показывать уже замаскированные данные из задачи 41, маскирование в UI заново не изобретать.
- REPL — реальная дыра в ногу: никакого автозапуска сохранённых сниппетов, только явный ввод пользователя, и всё в аудит.
- Кнопки «Перезапустить»/«Пауза» воркера трогают живой пайплайн: во время активной сессии предупредить, что она будет прервана.

## Готово когда
- [ ] Лог идёт в реальном времени, фильтры по уровню и модулю, поиск и автопрокрутка работают; на DEBUG интерфейс не подвисает.
- [ ] Уровень логирования меняется из вкладки на лету; папка логов открывается, архив баг-репорта собирается с показом состава.
- [ ] Таблица пайплайна показывает `STT raw → NLU intent → Action → Result` с таймингами каждой стадии и суммой, переход к строкам лога по `request_id` работает.
- [ ] Текст из поля ввода проходит весь пайплайн и выполняет команду без голоса; история ввода доступна стрелками.
- [ ] REPL выполняет код в контексте приложения, показывает результат и трассировку, не блокирует UI и открывается только после подтверждения риска.
- [ ] Панель воркеров показывает статус, аптайм, перезапуски и RAM; перезапуск воркера из UI работает.
- [ ] Тесты, ruff и mypy зелёные.
