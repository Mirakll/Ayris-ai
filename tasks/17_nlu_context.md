# Задача 17 — Контекст и follow-up

**Этап:** C — NLU и пайплайн | **Зависит от:** 16 | **Разделы ТЗ:** 5.2, 18

## Цель
Контекст диалога для follow-up команд: разрешение анафоры («закрой его»), команды «повтори» и «отмена», контекстные фильтры триггеров по активному окну.

## Что сделать
1. `nlu/context.py` — `DialogContext`: последняя выполненная команда с её слотами и результатом, последний упомянутый объект (приложение, окно, файл, URL) с типом, последний ответ помощника, активное окно и процесс, время суток, значения переменных из профиля. Хранение в памяти + персист последнего состояния в БД для восстановления после рестарта.
2. Время жизни контекста: TTL на follow-up окно (по умолчанию ~30 сек, настраивается), продление при каждой реплике, сброс по явной отмене, по смене профиля и по истечении. Отдельные TTL для «последнего объекта» и для «последнего ответа» (повторить ответ можно и позже).
3. Разрешение анафоры: местоимения и указательные («его», «её», «их», «это», «то же самое», «там») подставляются из последнего упомянутого объекта подходящего типа. «Открой браузер» → «закрой его» превращается в `close_app(app=chrome)`. Если подходящего объекта нет — переспрос голосом, а не молчаливый провал.
4. Команда «повтори» / «ещё раз» / «повтори последнее»: два режима — повтор последнего ответа (озвучить заново через `say()`) и повтор последнего действия (выполнить ту же команду с теми же слотами). Выбор по формулировке; опасные действия (питание, удаление) не повторяются без подтверждения.
5. Команда «отмена» / «стоп» / «отставить»: публикация `CancelRequested` — прерывание TTS (задача 12), отмена текущего действия/макроса, выход из follow-up диалога и сброс ожидания уточнения. Работает в любой момент, в том числе во время озвучки и во время выполнения длинного макроса.
6. Контекстные фильтры триггеров: у триггера опциональные условия активности — активное окно/процесс (`when_window: "*Photoshop*"`), время суток, значение переменной, текущий профиль. Матчер из задачи 15 получает предикат и отсекает неподходящие триггеры до разрешения конфликтов, чтобы одна и та же фраза значила разное в разных приложениях.
7. Ожидание уточнения (slot filling): если у команды не хватает обязательного слота — задать вопрос голосом, следующая реплика пользователя интерпретируется как ответ на него, с таймаутом и отменой. Состояние ожидания живёт в контексте.
8. Тесты сценариев из нескольких реплик: «открой браузер» → «закрой его»; «поставь таймер на 5 минут» → «отмени»; «который час» → «повтори»; истечение TTL сбрасывает анафору; одна фраза даёт разные команды при разном активном окне; уточнение недостающего слота и отмена посреди уточнения.

## Осторожно
- Контекст читается из пайплайна и пишется из нескольких мест — единая точка мутации с блокировкой, никаких правок полей извне.
- «Стоп» может быть и командой отмены, и частью пользовательской команды («стоп музыка») — отмена проверяется только на точное короткое совпадение и имеет высший приоритет, но не перехватывает более длинную специфичную фразу.
- Активное окно опрашивать через WinAPI лениво и с кэшем на сотни миллисекунд, а не на каждом матчинге.
- Повтор действия не должен зацикливаться: «повтори» не записывается в контекст как последнее действие.
- Восстановление контекста после рестарта не должно воскрешать ожидание уточнения — оно всегда сбрасывается при старте.

## Готово когда
- [ ] «Открой браузер» → «закрой его» закрывает именно браузер.
- [ ] По истечении TTL «закрой его» переспрашивает, а не закрывает случайное окно.
- [ ] «Повтори» озвучивает последний ответ, «ещё раз» повторяет последнее действие, опасное — только с подтверждением.
- [ ] «Айрис, стоп» прерывает озвучку и текущее действие в любой момент.
- [ ] Триггер с фильтром по активному окну срабатывает только в нужном приложении.
- [ ] Недостающий обязательный слот вызывает голосовое уточнение, ответ подставляется, отмена работает.
