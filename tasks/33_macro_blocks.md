# Задача 33 — Библиотека блоков

**Этап:** E — Макросы | **Зависит от:** 32, этап D | **Разделы ТЗ:** 7.2

## Цель
Полный набор блоков макро-редактора: обёртки над действиями этапа D по категориям таблицы 7.2, единая схема параметров для UI и документация каждого блока.

## Что сделать
1. `macros/blocks/catalog.py` — реестр блоков: каждый блок описывается `BlockMeta` (`type`, `category`, `title_ru`, `description_ru`, `icon`, `action_name` или собственный исполнитель, схема параметров из `ActionRegistry.describe`, пример использования). Блоки-обёртки над действиями строятся автоматически из реестра действий — никакого ручного дублирования схем.
2. Категории и состав по таблице 7.2 ТЗ:
   - **Голос/Звук**: `Say`, `PlaySound`, `StopSound`, `SetVolume`, `SetTTSVoice`.
   - **Ввод**: `KeyPress`, `KeyDown`, `KeyUp`, `TypeText`, `MouseClick`, `MouseMove`, `MouseDrag`, `MouseWheel`.
   - **Система**: `RunApp`, `RunShell`, `CloseApp`, `FocusWindow`, `WindowState`, `SetBrightness`, `SetWifi`, `SetBluetooth`, `PowerAction`, `Screenshot`, `ClipboardSet`, `ClipboardGet`.
   - **Яндекс Музыка**: `YMPlay`, `YMPause`, `YMNext`, `YMPrev`, `YMLike`, `YMSearch`, `YMPlaylist`.
3. Собственные блоки потока, которых нет в реестре действий: `Wait` (по мс, по секундам, по условию с таймаутом), `Sleep`. Ожидание кооперативно прерывается отменой из задачи 31.
4. **Сеть/Веб**: `WebRequest` (GET/POST, заголовки, тело, таймаут, парсинг JSON-ответа в переменную по JSON-path, ограничение размера ответа), `OpenURL`, `SearchWeb` (движок из настроек). Zero telemetry: запрос уходит только по явно указанному пользователем адресу.
5. **Уведомления**: `ToastNotify` (заголовок, текст, иконка, действие по клику), `OverlayLog` (строка в лог оверлея с уровнем).
6. Палитра для UI (задачи 52/53): `list_categories()` и `list_blocks(category)` с иконками и русскими подписями, поиск по названию и описанию, порядок категорий как в ТЗ. UI рисует форму параметров по схеме, без хардкода под каждый блок.
7. Документация: для каждого блока `description_ru` и минимум один пример параметров — генерируемая страница для `docs/` (задача 73) собирается из каталога, а не пишется руками.
8. Тесты: каждый блок из таблицы 7.2 присутствует в каталоге; у каждого валидная схема параметров и пример, который проходит валидацию; блоки-обёртки вызывают ровно то действие, которое заявлено; `Wait` по условию завершается по таймауту и прерывается отменой.

## Файлы
`src/ayris/actions/macros/blocks/catalog.py`, `blocks/flow.py`, `blocks/web.py`, `blocks/notify.py`, `src/ayris/actions/macros/docs.py`, `tests/unit/test_block_catalog.py`

## Осторожно
- Не дублировать логику действий этапа D: блок — тонкая обёртка, вся реализация остаётся в `actions/system/*` и вызывается через реестр.
- Если действие этапа D ещё не готово, блок всё равно должен быть в каталоге и честно сообщать «действие недоступно», а не падать при открытии редактора.
- `RunShell` и `WebRequest` — потенциально опасные блоки: помечать `is_dangerous`, чтобы подхватилась задача 40.

## Готово когда
- [ ] Все блоки из таблицы 7.2 ТЗ есть в каталоге и проходят проверку схемы.
- [ ] Палитра отдаёт категории с иконками и русскими подписями, поиск работает.
- [ ] `WebRequest` кладёт разобранный JSON в переменную, доступную следующим блокам.
- [ ] `Wait` по условию не блокирует поток намертво и прерывается отменой команды.
- [ ] Страница документации блоков генерируется из каталога.
- [ ] Тесты, ruff и mypy зелёные.
