# Задача 13 — TTS облачный и роутер

**Этап:** B — Аудио и речь | **Зависит от:** 12 | **Разделы ТЗ:** 4.2, 4.3

## Цель
Облачный синтез речи через четыре провайдера, роутер с фоллбеком облако→локально и единый `say(text)` для всей остальной системы.

## Что сделать
1. Реализации `TtsEngine` на httpx: `elevenlabs_engine.py`, `yandex_tts_engine.py` (SpeechKit TTS), `google_tts_engine.py` (Cloud TTS), `azure_tts_engine.py`. Общий `cloud_base.py` — креденшелы из keyring, сборка запроса, разбор ответа в `AudioChunk`, получение списка голосов провайдера с кэшированием.
2. Стриминговый синтез там, где провайдер его поддерживает (ElevenLabs, Azure): отдавать чанки по мере прихода в плеер из задачи 12, чтобы озвучка начиналась < 1.5 сек по ТЗ.
3. `audio/tts/router.py` — `TtsRouter`: выбор движка по конфигу, фоллбек облако→локально при сетевой ошибке, таймауте или отсутствии ключа, с событием и уведомлением в UI. Реакция на `OnlineStatusChanged` из задачи 11: в офлайне сразу идти в локальный движок, не тратя таймаут.
4. Единый публичный API `say(text, *, voice=None, speed=None, priority=None) -> SpeechHandle` — точка входа для NLU, действий, макросов, плагинов и системных уведомлений. Никто, кроме роутера, движки TTS напрямую не вызывает. `SpeechHandle` даёт отмену и ожидание завершения.
5. Настройки голоса едины для локальных и облачных: голос, скорость 0.5–2.0, тон, громкость; валидация диапазонов и приведение параметров к нативным единицам провайдера (у каждого своя шкала). Тест воспроизведения для окна настроек: `preview(voice, params)` на короткой фразе, без записи в историю.
6. Учёт лимитов и квот: маппинг 401/429/402 в типизированные исключения, счётчик израсходованных символов на провайдера в БД, предупреждение в UI при приближении к лимиту из конфига, ошибка квоты не ретраится — сразу фоллбек на локальный движок.
7. Тесты с замоканными HTTP-ответами: разбор аудио-ответа каждого провайдера, стриминговый вариант, 401/429/таймаут → фоллбек на локальный движок, приведение speed/pitch к шкале провайдера, подсчёт символов, `preview` не пишет в историю.

## Осторожно
- Провайдеры отдают разные форматы (mp3, ogg-opus, pcm) — декодирование в общий PCM в одном месте, плеер знает только PCM.
- Шкалы параметров несовместимы: скорость у Google в `speakingRate`, у Azure в процентах прозы SSML, у Yandex отдельным полем — маппинг с тестами, а не «на глаз».
- Не логировать текст запросов целиком, если в нём могут быть пользовательские данные, и никогда не логировать ключи.
- Фоллбек не должен приводить к двойной озвучке: перед повтором на локальном движке убедиться, что из облачного ничего не попало в плеер.

## Готово когда
- [ ] Все четыре облачных провайдера озвучивают фразу на замоканных ответах и дают PCM в плеер.
- [ ] Сетевая ошибка или 429 приводят к озвучке той же фразы локальным движком, без дублирования звука.
- [ ] `say(text)` — единственная точка входа, остальные модули не знают, облако это или локально.
- [ ] Скорость, тон и громкость применяются одинаково у локальных и облачных голосов, диапазоны валидируются.
- [ ] Тест воспроизведения из настроек работает и не пишет в историю диалога.
- [ ] Счётчик символов растёт, предупреждение о приближении к лимиту появляется.
