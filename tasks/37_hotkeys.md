# Задача 37 — Глобальные хоткеи

**Этап:** F — Хоткеи и интеграция ядра | **Зависит от:** 04 | **Разделы ТЗ:** 8.1 (вкладка 5), 13

## Цель
Слой глобальных горячих клавиш: регистрация через WinAPI, системные хоткеи помощника и пользовательские на команды, детекция конфликтов, захват комбинации в UI, работа в играх.

## Что сделать
1. `utils/hotkeys.py` — модель комбинации `Hotkey` (модификаторы + клавиша) с парсингом и нормализацией строк (`ctrl+alt+v`, `Ctrl + Alt + V`, VoiceAttack- и AHK-нотации), сериализацией в канонический вид, русской подписью для UI. Это единственный парсер комбинаций в проекте.
2. `utils/hotkey_manager.py` — регистрация через `RegisterHotKey` WinAPI в выделенном потоке с собственным окном-приёмником сообщений (`WM_HOTKEY`), снятие через `UnregisterHotKey`, безопасное завершение потока. Разбор кодов ошибок WinAPI (`ERROR_HOTKEY_ALREADY_REGISTERED`) в понятное сообщение с указанием, кто именно занят.
3. Системные хоткеи помощника: PTT, переключение режима Wake Word, показать/скрыть оверлей, Mute микрофона, отмена текущего действия. Значения по умолчанию и переопределение из конфига; каждый хоткей публикует типизированное событие в event bus, а не вызывает подсистемы напрямую.
4. Пользовательские хоткеи на команды: подписка на триггеры типа `hotkey` из БД, `WM_HOTKEY` → запуск команды через движок макросов. Отключённая команда свой хоткей не занимает.
5. Детекция конфликтов: между своими хоткеями (одна комбинация на две команды) — при сохранении в UI, с указанием конфликтующей команды; с системными и чужими — по отказу `RegisterHotKey`, с предложением выбрать другую комбинацию. Список занятых комбинаций доступен вкладке 55.
6. Захват комбинации в UI: API «нажмите сочетание» — временный низкоуровневый перехват (`SetWindowsHookEx WH_KEYBOARD_LL`) на время диалога, возврат нормализованной комбинации, отсечение одиночных модификаторов и запрещённых клавиш, отмена по Esc.
7. Поведение PTT: нажал-держи-говори, отпустил — обработка. Отслеживание удержания и отпускания (`RegisterHotKey` даёт только нажатие — нужен опрос состояния клавиши или низкоуровневый хук), минимальная длительность удержания против случайных касаний, публикация `PttPressed` / `PttReleased`.
8. Работа в играх: опциональный бэкенд на `interception` driver / Raw Input за общим интерфейсом `HotkeyBackend` — включается в настройках, при отсутствии драйвера graceful-фоллбек на WinAPI с сообщением в UI.
9. Перерегистрация без рестарта: смена комбинации в настройках или включение/выключение команды применяются на лету (снять — зарегистрировать заново), реакция на события изменения конфига и hot reload команд.
10. Тесты: парсинг и нормализация комбинаций во всех нотациях, детект конфликта своих хоткеев, обработка отказа регистрации (замоканный WinAPI), логика PTT по искусственным событиям нажатия/отпускания, перерегистрация при смене настроек.

## Осторожно
- `RegisterHotKey` привязан к потоку: регистрировать и снимать нужно из того же потока, где крутится цикл сообщений, иначе снятие молча не сработает.
- Глобальный низкоуровневый хук держать только на время захвата комбинации в UI: постоянный хук — это тормоза системы и повод для антивируса.
- Хоткеи не работают поверх окон, запущенных с более высокими правами; сказать об этом пользователю честно, а не молчать.
- `interception` требует установки драйвера и прав администратора — это опция, а не обязательное условие запуска.

## Готово когда
- [ ] Системные хоткеи (PTT, Wake toggle, оверлей, Mute, отмена) регистрируются и публикуют события.
- [ ] Хоткей команды запускает её; выключение команды освобождает комбинацию.
- [ ] Занятая системой комбинация даёт понятное сообщение, а не тихий отказ.
- [ ] Конфликт двух своих команд обнаруживается до сохранения.
- [ ] Захват «нажмите сочетание» возвращает нормализованную комбинацию и отменяется по Esc.
- [ ] PTT корректно различает удержание и отпускание; смена комбинации применяется без рестарта.
- [ ] Тесты, ruff и mypy зелёные.
