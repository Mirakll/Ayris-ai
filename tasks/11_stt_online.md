# Задача 11 — STT онлайн и роутер Auto

**Этап:** B — Аудио и речь | **Зависит от:** 10 | **Разделы ТЗ:** 3.1, 3.3

## Цель
Облачное распознавание речи через четыре провайдера и роутер Online/Offline/Auto с автоматическим фоллбеком на офлайн при потере сети.

## Что сделать
1. Реализации `SttEngine` на общем httpx-клиенте: `google_engine.py` (Google Cloud Speech-to-Text), `yandex_engine.py` (SpeechKit), `azure_engine.py` (Azure Speech), `openai_engine.py` (Whisper API). Каждая приводит ответ провайдера к `TranscriptResult` из задачи 10, включая confidence и тайминги, где провайдер их отдаёт.
2. Ключи и токены — только из keyring по имени провайдера, никогда из `config.toml` и никогда в логах. Общий базовый класс `CloudSttEngine` с загрузкой креденшелов, сборкой запроса, разбором ошибок HTTP и маппингом кодов (401 — неверный ключ, 429 — квота, 5xx — временная) в типизированные исключения из `core/errors.py`.
3. `core/connectivity.py`: детектор доступности интернета. Не пинговать постоянно: основной сигнал — факт сетевой ошибки при реальном запросе, плюс редкая фоновая проверка (интервал из конфига, лёгкий HEAD-запрос) и реакция на смену состояния сетевого адаптера. Публикация `OnlineStatusChanged(online: bool, reason)`.
4. `audio/stt/router.py` — `SttRouter`: режимы Online / Offline / Auto. В Auto стартует с облачного движка, при сетевой ошибке или таймауте переключается на офлайн (если модель установлена), публикует событие и уведомление в UI, затем пробует вернуться в онлайн по восстановлению связи. Если офлайн-модели нет — понятное голосовое и UI-сообщение вместо тихого отказа.
5. Таймауты (connect/read отдельно) и ретраи с экспоненциальной задержкой и джиттером, лимит попыток из конфига. Ошибки квоты не ретраить, сразу фоллбек. Общее время на распознавание ограничено, чтобы пайплайн не висел.
6. Единый вход для остальной системы: `transcribe(audio)` у роутера, вызывающий код не знает, какой движок сработал; фактический движок отражён в `TranscriptResult.engine` и в логе пайплайна вместе с таймингом.
7. Тесты с замоканными HTTP-ответами (respx или мок транспорта httpx): успешный разбор ответа каждого провайдера, 401/429/5xx, таймаут; переключение Auto на офлайн при сетевой ошибке и возврат в онлайн; отсутствие ключа в keyring.

## Осторожно
- Переключение Online↔Offline по ТЗ должно занимать < 2 сек: офлайн-модель для Auto держать предзагруженной или грузить заранее в фоне, иначе фоллбек упрётся в загрузку модели.
- Не логировать тела запросов с аудио и заголовки с токенами.
- Yandex и Azure требуют разных схем авторизации (IAM/API-key, региональный endpoint) — регион и endpoint в конфиг, не хардкод.
- Zero telemetry: фоновая проверка связи не должна ходить никуда, кроме адреса из конфига, и отключается вместе с онлайн-режимом.
- `httpx==0.28.1` уже стоит в `pyproject.toml`, а вот в `requirements-ci.txt` его пока нет: как только код начнёт импортировать httpx на верхнем уровне, пин надо добавить туда той же версией. Расхождение ловит `tests/unit/test_packaging.py`, отсутствие пакета при живом импорте — тоже. Мок-транспорт лучше брать встроенный в httpx: новая зависимость вроде respx требует пина сразу в оба файла, а выгоды над `MockTransport` даёт немного.
- В Linux-песочнице у keyring нет бэкенда, поэтому тесты подсовывают фейковое хранилище; проверка с настоящим Credential Manager идёт только на Windows и помечается `pytest.mark.skipif(sys.platform != "win32")`, чтобы прогон в песочнице оставался зелёным.

## Готово когда
- [ ] Каждый из четырёх провайдеров возвращает корректный `TranscriptResult` на замоканном ответе.
- [ ] В режиме Auto сетевая ошибка приводит к офлайн-распознаванию той же фразы и событию `OnlineStatusChanged`.
- [ ] После восстановления связи роутер возвращается в онлайн без рестарта приложения.
- [ ] Ошибка квоты (429) не ретраится и даёт понятное сообщение пользователю.
- [ ] Ключи читаются из keyring, в логах их нет. — **проверяет CI на windows-раннере**
- [ ] Тесты с мок-HTTP зелёные, реальная сеть в тестах не нужна.
- [ ] Хотя бы один провайдер распознаёт живую фразу с настоящим ключом. — **проверяешь ты руками**: нужен реальный аккаунт сервиса; моки не ловят расхождение с настоящим форматом запроса
