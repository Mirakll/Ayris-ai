# Задача 22 — Яркость и мониторы

**Этап:** D — Системные действия | **Зависит от:** 19 | **Разделы ТЗ:** 6 (Экран), 18

## Цель
Управление яркостью встроенного дисплея и внешних мониторов плюс перечисление мониторов с их геометрией и DPI для per-monitor действий по всему приложению.

## Что сделать
1. `utils/monitors.py`: перечисление мониторов через `EnumDisplayMonitors` + `GetMonitorInfoW` — модель `MonitorInfo` (id, отображаемое имя, серийник/устройство, координаты и размер рабочей области, разрешение, DPI через `GetDpiForMonitor`, флаг primary). Общий модуль: им пользуются оверлей, скриншоты (задача 26) и ввод (задача 23).
2. Адресация монитора: единый резолвер строки в `MonitorInfo` — `primary`, `external_1..N` (по порядку слева направо), по подстроке имени, по номеру. Один разбор адреса на всё приложение, чтобы `SetBrightness(monitor="external_1")` из примера в ТЗ и скриншот конкретного монитора использовали одну логику.
3. `actions/system/brightness.py`: яркость встроенного дисплея через WMI (`WmiMonitorBrightnessMethods.WmiSetBrightness` / `WmiMonitorBrightness`), внешних — через DDC/CI библиотекой `monitorcontrol`. Абсолютная установка 0–100 и относительная («ярче/темнее на N%»), шаг из конфига (`[actions.display] brightness_step`). Действия `SetBrightness`, `AdjustBrightness`, `ListMonitors`.
4. Кэш возможностей мониторов: при первом обращении определить и запомнить поддерживаемый способ управления (WMI / DDC-CI / нет), диапазон значений и время отклика; инвалидация кэша при смене конфигурации дисплеев (`WM_DISPLAYCHANGE`). DDC/CI-запросы медленные (десятки–сотни мс) — не дёргать их синхронно на каждый вызов.
5. Обработка мониторов без поддержки: понятная русская ошибка через `ActionError` («Монитор ... не поддерживает управление яркостью») вместо исключения из библиотеки; групповые операции (все мониторы) выполняются best-effort и возвращают отчёт по каждому монитору.
6. Типизированные результаты: `ListMonitors` возвращает список `MonitorInfo`, `SetBrightness` — итоговый уровень по каждому затронутому монитору (для озвучивания).
7. Тесты: резолвер адреса монитора на фикстурах конфигураций (один экран, два экрана, primary справа, разный DPI), клампинг и относительный шаг, поведение при отсутствии поддержки DDC/CI (мок), логика кэша и инвалидации.

## Осторожно
- DDC/CI работает не на всех мониторах и кабелях (часто отваливается на HDMI и через KVM), таймауты долгие — обязательно ограничение времени и фоллбек.
- WMI-яркость доступна обычно только на ноутбуках со встроенной панелью, на десктопе метода просто нет.
- Процесс должен быть per-monitor DPI aware, иначе координаты и DPI приходят виртуализованными и неверными.
- Не опрашивать все мониторы по DDC/CI на старте приложения — это заметная задержка запуска, только лениво и в фоне.

## Готово когда
- [ ] «яркость 70», «ярче», «темнее на 20 процентов» работают на встроенном дисплее.
- [ ] Внешний монитор с DDC/CI управляется, без поддержки — внятное сообщение, а не трейсбек.
- [ ] `ListMonitors` отдаёт корректные имена, разрешение, DPI и координаты при разном масштабировании.
- [ ] Адрес `primary` / `external_1` / имя резолвится одинаково во всех действиях.
- [ ] Переподключение монитора инвалидирует кэш возможностей.
- [ ] Тесты зелёные.
