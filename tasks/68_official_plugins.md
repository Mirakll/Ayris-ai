# Задача 68 — Официальные плагины

**Этап:** I — Плагины, сборка, релиз | **Зависит от:** 66 | **Разделы ТЗ:** 9.3

## Цель
Набор эталонных плагинов, которые одновременно решают реальные задачи пользователя и служат образцом использования SDK.

## Что сделать
1. `plugins/home_assistant/`: подключение к Home Assistant по REST/WebSocket или к брокеру MQTT — адрес и токен в настройках плагина, список сущностей, голосовые команды включения, выключения и установки значения («включи свет на кухне», «яркость лампы 30»), проверка соединения. Разрешения: `network`, `settings`, `commands_register`.
2. `plugins/discord/`: Discord RPC — статус и Rich Presence, mute и deafen, переключение канала. Понятное сообщение, если клиент Discord не запущен.
3. `plugins/obsidian/`: создание заметки голосом в указанный vault (шаблон имени, дата, папка), добавление строки в дневную заметку, поиск по vault с озвучкой найденного заголовка. Разрешение `fs` с ограничением области папкой vault.
4. `plugins/steam/`: запуск игры по названию через `steam://rungameid/`, разбор локальной библиотеки из `libraryfolders.vdf` и манифестов приложений для сопоставления названия с id, фаззи-матчинг названия, статус «Steam запущен / игра запущена».
5. `plugins/browser_automation/`: Playwright — открытие страницы, поиск, заполнение полей, клик по селектору как действия, доступные макросам. Отдельный профиль браузера, честное предупреждение о размере зависимости и о том, что браузер надо установить командой Playwright.
6. Единый вид на каждый плагин: `manifest.json` с минимально необходимыми разрешениями, `README.md` с описанием, требованиями и списком примеров команд, набор готовых команд для импорта, комментарии там, где показывается приём работы с SDK. Ограничиться рабочим минимумом — эти плагины образцы, а не полноценные продукты.
7. Тесты: моки внешних сервисов (HTTP Home Assistant, MQTT-брокер, RPC Discord, файловая система vault и библиотеки Steam), проверка регистрации команд и корректного поведения при недоступном сервисе. Playwright-плагин — smoke-тест, помеченный как опциональный.

## Файлы
`plugins/home_assistant/*`, `plugins/discord/*`, `plugins/obsidian/*`, `plugins/steam/*`, `plugins/browser_automation/*`, `tests/integration/test_official_plugins.py`

## Осторожно
- Плагины пользуются только публичным SDK: если чего-то не хватает, это повод дополнить SDK в задаче 66, а не лезть во внутренности приложения.
- Токены Home Assistant и Discord — в keyring, не в `manifest.json` и не в логах.
- Playwright тянет сотни мегабайт: не включать в основной дистрибутив, ставить по требованию.
- Не тестировать против живых сервисов в CI — только моки и фикстуры.

## Готово когда
- [ ] Каждый плагин устанавливается, включается и регистрирует свои команды.
- [ ] Голосовое управление устройством Home Assistant работает на моке брокера и на реальном стенде, если он доступен.
- [ ] «Айрис, запусти Dota» находит игру в локальной библиотеке Steam и запускает её.
- [ ] Создание заметки голосом кладёт файл в vault Obsidian, поиск находит его.
- [ ] Недоступный внешний сервис даёт понятное сообщение, а не исключение в лог.
- [ ] У каждого плагина есть README с примерами команд; тесты на моках зелёные.
