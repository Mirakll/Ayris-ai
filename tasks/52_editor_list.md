# Задача 52 — Редактор команды: списочный режим

**Этап:** G — Интерфейс | **Зависит от:** 51, 33 | **Разделы ТЗ:** 8.4, 7.3

## Цель
Правая панель вкладки «Команды»: полный редактор выбранной команды со списком блоков действий, триггерами, переменными и звуками. Это основная рабочая форма, нодовый режим задачи 53 работает на той же модели.

## Что сделать
1. Шапка команды (`gui/widgets/editor_header.py`): имя, описание, теги (чипы с автодополнением из существующих), тумблер «Включена», приоритет, кулдаун в мс, `require_admin` с пояснением про UAC. Валидация на месте: пустое имя и дубликат имени в папке подсвечиваются до сохранения.
2. Секция «Триггеры» (`gui/widgets/trigger_list.py`): список триггеров с добавлением по типу — голосовая фраза (поле фразы, тумблеры fuzzy и regex, порог fuzzy, приоритет, проверка компиляции regex и подсветка именованных групп как слотов), захват хоткея через API задачи 37, выбор системного события со фильтром, настройка расписания (время или cron с человекочитаемой расшифровкой). Проверка конфликтов при вводе: занятая комбинация или совпадающая фраза другой команды показывается сразу, с именем конфликтующей команды.
3. Секция «Действия» (`gui/widgets/action_list.py`): список блоков с drag-and-drop порядком, вложенность ветвей `If`/`Else`/`While`/`For`/`Try`/`Catch` отступами и линиями связи, сворачивание ветки, включение/выключение и комментарий блока, дублирование, копирование-вставка блоков между командами, удаление с undo. Перетаскивание внутрь ветки и наружу с корректным пересчётом пути до блока.
4. Палитра блоков (`gui/widgets/block_palette.py`): категории и блоки из каталога задачи 33 с иконками и русскими подписями, поиск по названию и описанию, вставка по двойному клику и перетаскиванием в нужное место списка, пометка опасных блоков (`is_dangerous`) и недоступных действий.
5. Панель параметров выбранного блока (`gui/widgets/param_form.py`): форма строится автоматически из pydantic-схемы действия (`ActionRegistry.describe`) — типы полей по аннотациям (строка, число со слайдером, булево, выбор из перечисления, путь к файлу, клавиша, длительность), значения по умолчанию, подсказки из описания поля, поля с признаком `secret` не показываются в открытом виде. Автодополнение `{var}` и слотов триггера в текстовых полях. Никакого хардкода формы под конкретный блок.
6. Секция «Переменные» (`gui/widgets/variable_table.py`): таблица имя / тип / scope (`local`/`profile`/`global`) / значение по умолчанию / persistent, добавление и удаление, проверка соответствия значения типу, подсветка переменных, на которые никто не ссылается, и ссылок на необъявленные переменные (данные от валидатора задачи 30).
7. Секция «Звуки» (`gui/widgets/sound_binding.py`): привязка к стадиям `OnStart` / `OnSuccess` / `OnError`, источник — встроенная библиотека, генерация TTS по тексту или импорт `.wav/.mp3/.ogg`, предпрослушивание с кнопкой остановки, показ длительности файла.
8. Кнопка «Тест»: запуск команды прямо из редактора через отладчик задачи 35 с подменой слотов, показ результата и лога стадий с таймингами в нижней панели; для опасных блоков — режим «сухого прогона» либо явное подтверждение. Сохранение перед тестом с прогоном валидатора задачи 30 и переходом по клику на проблемный блок.

## Осторожно
- Модель редактора — `CommandModel` задачи 30 и ничего кроме: редактор не заводит своё представление команды, иначе нодовый режим и hot reload разъедутся.
- Генератор формы параметров обязан корректно вести себя с незнакомым типом поля: показать текстовое поле и предупреждение, а не упасть при открытии команды.
- Предпрослушивание звука и «Тест» идут через существующие TTS/движок макросов, никаких прямых вызовов аудио-библиотек из виджета.
- Тяжёлые операции (компиляция regex по всему списку, валидация, генерация TTS) не в UI-потоке.

## Готово когда
- [ ] Команда из дерева открывается в редакторе, правки в шапке, триггерах, блоках, переменных и звуках сохраняются и читаются обратно без потерь.
- [ ] Блок добавляется из палитры, перетаскивается внутрь ветки `If` и обратно, порядок сохраняется.
- [ ] Форма параметров любого блока из каталога задачи 33 строится автоматически и валидирует ввод по схеме.
- [ ] Конфликт голосовой фразы или хоткея с другой командой показывается до сохранения, с именем конфликтующей команды.
- [ ] Звук привязывается к стадии и проигрывается по кнопке предпрослушивания.
- [ ] Кнопка «Тест» выполняет команду с подменёнными слотами и показывает лог стадий с таймингами; ошибки валидации ведут к нужному блоку.
- [ ] Тесты, ruff и mypy зелёные.
