# Задача 72 — Инсталлер и автообновления

**Этап:** I — Плагины, сборка, релиз | **Зависит от:** 71 | **Разделы ТЗ:** 16.2, 16.3

## Цель
Инсталлер Inno Setup, который ставит и удаляет приложение чисто, и автообновления из GitHub Releases с проверкой целостности и откатом при неудаче.

## Что сделать
1. `build/inno_setup.iss`: установка в `Program Files\Ayris`, ярлыки в меню Пуск и опционально на рабочем столе, регистрация протокола `ayris://` (с обработчиком в приложении), запись автозапуска в HKCU по выбору пользователя, версия и метаданные из одного источника со сборкой, русская локализация экранов установщика.
2. Деинсталлятор: снятие автозапуска и регистрации протокола, удаление файлов программы, отдельный вопрос «удалить пользовательские данные (профиль, команды, модели, логи) или сохранить» с сохранением по умолчанию. После удаления с сохранением данных повторная установка подхватывает прежний профиль.
3. Тихий режим: `/silent` и `/verysilent` для обновлений — без диалогов, с корректным закрытием работающего экземпляра (сигнал приложению на graceful shutdown вместо убийства процесса) и запуском новой версии после установки.
4. `core/updater.py`: проверка GitHub Releases по расписанию (при запуске / раз в день) и по кнопке, сравнение версий по semver с учётом канала, скачивание инсталлера с прогрессом, проверка SHA256 из релиза (и подписи, когда сертификат появится), запуск тихой установки, перезапуск приложения. Отказ при несовпадении хеша — без установки, с сообщением.
5. Откат и устойчивость: снимок текущей версии и профиля перед обновлением, обработка неудачной установки (возврат на предыдущую версию, сообщение с ссылкой на лог), защита от повторного одновременного обновления, продолжение работы, если сервер релизов недоступен.
6. Каналы и changelog: стабильный и предрелизный канал (переключатель в настройках, предрелизы по умолчанию выключены), показ changelog из тела релиза в UI перед установкой, кнопка «Пропустить эту версию».
7. `gui/tabs/updates.py`: вкладка Обновления — текущая версия и канал, кнопка «Проверить сейчас» с состоянием, прогресс загрузки, changelog, тумблер автопроверки; сюда же встраивается UI менеджера моделей из задачи 50.
8. Заготовка под code signing: место в сборке для подписи exe и инсталлера EV-сертификатом (переменные окружения для thumbprint и timestamp-сервера, шаг подписи, пропускаемый при отсутствии сертификата), проверка подписи в апдейтере с мягким режимом, пока подписи нет.

## Файлы
`build/inno_setup.iss`, `build/sign.py`, `src/ayris/core/updater.py`, `src/ayris/core/protocol_handler.py`, `src/ayris/gui/tabs/updates.py`, `tests/unit/test_updater.py`

## Осторожно
- Обновление затрагивает установленную систему: без явного согласия пользователя ничего не скачивается и не ставится, автопроверка — единственное сетевое обращение и оно отключаемо (zero telemetry).
- Установка поверх работающего приложения ломается на занятых файлах: сначала корректное завершение экземпляра, потом установка.
- Не пытаться писать в `Program Files` из приложения: профиль и модели — только в пользовательских путях.
- Реестр и протокол трогать аккуратно: деинсталлятор обязан убирать за собой всё, что добавил.

## Готово когда
- [ ] Инсталлер ставит приложение, создаёт ярлыки, регистрирует `ayris://`, автозапуск включается по выбору.
- [ ] Деинсталлятор убирает программу и реестровые записи, данные удаляет или сохраняет по выбору пользователя.
- [ ] Тихая установка поверх работающей версии проходит с корректным закрытием и перезапуском.
- [ ] Апдейтер находит новую версию, показывает changelog, проверяет SHA256 и ставит обновление.
- [ ] Битый файл или неудачная установка приводят к откату и понятному сообщению, а не к нерабочему приложению.
- [ ] Переключение канала работает, предрелизы по умолчанию выключены; шаг подписи готов к появлению сертификата.
