# Задача 67 — Вкладка Плагины

**Этап:** I — Плагины, сборка, релиз | **Зависит от:** 43, 66 | **Разделы ТЗ:** 9.4, 8.1 (вкладка 7)

## Цель
Управление плагинами из интерфейса: список установленных, включение и удаление, просмотр логов, установка кастомного плагина с подтверждением разрешений.

## Что сделать
1. Список установленных плагинов карточками: имя, версия, автор, описание, статус (включён / выключен / сбойный / несовместимый), выданные разрешения иконками с расшифровкой при наведении. Сортировка и поиск по имени, отдельная пометка sandboxed-плагинов.
2. Управление плагином: тумблер включения с применением без рестарта, кнопка удаления с подтверждением и выбором «удалить данные плагина или оставить», кнопка «Открыть папку плагина». Для сбойного плагина — кнопка «Перезагрузить» и текст последней ошибки прямо в карточке.
3. Просмотр логов плагина: панель с его лог-файлом, фильтр по уровню, автопрокрутка, кнопка «Скопировать» для отправки автору. Ошибки последнего запуска подсвечиваются.
4. `gui/widgets/permission_dialog.py`: кнопка «+ Добавить кастомный плагин» — выбор папки, валидация манифеста через задачу 65 с показом конкретной ошибки при провале, затем диалог со списком запрашиваемых разрешений, объяснением риска каждого простым языком и явной кнопкой согласия. Отказ прерывает установку, код плагина до согласия не исполняется.
5. Детали плагина: список зарегистрированных им команд (с переходом в дерево команд задачи 51) и хоткеев (с проверкой конфликтов через задачу 55), чтобы было видно, что плагин реально добавил в систему.
6. Настройки плагина: если плагин объявил схему настроек через SDK, отрисовать форму по схеме и сохранять значения в его пространство настроек; если нет — секция не показывается.
7. Заглушка раздела маркетплейса: место в интерфейсе с честной подписью «появится позже», без нерабочих кнопок и без сетевых запросов.
8. Тесты pytest-qt на моках менеджера плагинов: отрисовка списка со всеми статусами, тумблер включения, диалог разрешений с отказом и согласием, показ ошибки битого манифеста.

## Файлы
`src/ayris/gui/tabs/plugins.py`, `src/ayris/gui/widgets/plugin_card.py`, `src/ayris/gui/widgets/permission_dialog.py`, `src/ayris/gui/widgets/plugin_log_view.py`, `tests/unit/test_tab_plugins.py`

## Осторожно
- Диалог разрешений — последний барьер перед чужим кодом: формулировки на русском и по делу, никаких «Разрешить всё» одной кнопкой по умолчанию.
- Установка и загрузка плагина не выполняются в UI-потоке; на время операции интерфейс остаётся отзывчивым.
- Заглушка маркетплейса не должна никуда ходить по сети — zero telemetry.
- Список команд и хоткеев берётся из реестра, а не из манифеста: показывать нужно фактически зарегистрированное.

## Готово когда
- [ ] Все установленные плагины видны с корректным статусом и разрешениями.
- [ ] Тумблер включает и выключает плагин без перезапуска приложения.
- [ ] Добавление плагина из папки проходит валидацию и требует явного согласия на разрешения.
- [ ] Битый манифест показывает конкретную причину отказа, а не общее «ошибка».
- [ ] Логи и последняя ошибка плагина доступны из его карточки.
- [ ] Команды и хоткеи плагина видны в деталях; тесты pytest-qt зелёные.
