# Задача 50 — UI менеджера моделей

**Этап:** G — Интерфейс | **Зависит от:** 43, 14 | **Разделы ТЗ:** 8.1 (вкладка 9), 3.3, 16.3

## Цель
Вкладка «Обновления»: визуальная часть менеджера моделей поверх бэкенда задачи 14 плюс секция автообновлений приложения.

## Что сделать
1. `gui/widgets/model_manager.py`: список доступных моделей из каталога, сгруппированный по категориям STT / TTS / Wake / LLM. Карточка модели: название, движок, размер, язык, описание и требования (RAM, GPU), статус — доступна / скачивается / установлена / повреждена / отсутствует на диске.
2. Загрузка: кнопка «Скачать» с прогресс-баром, скоростью и оставшимся временем, кнопка отмены, возобновление прерванной загрузки с места обрыва (Range из задачи 14), очередь при нескольких загрузках, продолжение фоновой загрузки при переключении на другую вкладку с индикацией в навигации.
3. Управление установленными: галочка «Установлено», выбор активной модели на вид и движок (радио внутри группы, публикует `ActiveModelChanged`), удаление с диалогом подтверждения и запретом удалить активную без предупреждения, показ занятого моделями места по категориям и суммарно плюс свободного места на диске.
4. Целостность: кнопка проверки SHA256 для установленной модели с индикацией результата (совпало / повреждена / файл отсутствует) и предложением перекачать; та же индикация автоматически после завершения загрузки.
5. Фильтр и поиск: поле поиска по названию, движку и описанию, фильтры по категории, языку и статусу «только установленные», пустое состояние из задачи 42, когда ничего не найдено.
6. `gui/tabs/updates.py`: секция автообновлений приложения — режим проверки (при запуске / раз в день / только вручную), кнопка «Проверить сейчас» с результатом, текущая и доступная версия, changelog из GitHub Releases в читаемом виде, кнопка загрузки и установки обновления с прогрессом. Вкладка собирает секцию обновлений и виджет менеджера моделей.
7. Обработка ошибок: нет сети, 404 на URL модели, недостаточно места, битый архив — понятное сообщение по-русски в карточке модели, а не в логе, с действием «Повторить».

## Файлы
`src/ayris/gui/tabs/updates.py`, `src/ayris/gui/widgets/model_manager.py`, `src/ayris/gui/widgets/model_card.py`, `src/ayris/gui/widgets/download_progress.py`, `tests/unit/test_model_manager_ui.py`

## Осторожно
- Вся работа с сетью и диском — в бэкенде задачи 14: UI только подписывается на события прогресса и вызывает API, никаких `httpx` во вкладке.
- Модели весят гигабайты: прогресс приходит часто, обновлять виджет не чаще ~10 раз в секунду, иначе UI начнёт тормозить на загрузке.
- Закрытие окна настроек не должно отменять загрузку — она живёт в приложении, а не во вкладке.
- Свободное место проверять до старта загрузки и показывать это пользователю заранее.

## Готово когда
- [ ] Каталог моделей отображается по категориям с размером, языком, описанием и требованиями.
- [ ] Загрузка идёт с прогрессом и скоростью, отменяется и возобновляется с места обрыва.
- [ ] Установленные модели отмечены, активная выбирается и публикует `ActiveModelChanged`, удаление подтверждается.
- [ ] Занятое место по категориям и свободное на диске показаны и сходятся с реальностью.
- [ ] Проверка SHA256 показывает результат, повреждённую модель предлагает перекачать.
- [ ] Поиск и фильтры работают, ошибки сети и места объясняются по-русски с кнопкой «Повторить».
- [ ] Секция автообновлений проверяет версию, показывает changelog и ставит обновление.
