# Задача 63 — Режимы NLU, промпты, память

**Этап:** H — LLM | **Зависит от:** 62, 18 | **Разделы ТЗ:** 5.1, 5.4, 20 этап 3

## Цель
Встроить LLM в пайплайн: три режима распознавания, системные промпты чата и NLU, история диалога с суммаризацией и вызов встроенных действий моделью вместо галлюцинаций.

## Что сделать
1. `nlu/llm/modes.py`: режимы `ai_only` (всё уходит в LLM, ответ озвучивается), `hybrid` (сначала матчинг команд из задач 15–17, при промахе или низкой уверенности — LLM), `commands_only` (LLM не используется и его воркер не поднимается). Подключение к пайплайн-диспетчеру задачи 18 одной точкой, переключение режима на лету без рестарта.
2. `resources/prompts/chat.txt` и `nlu.txt` + `nlu/llm/prompts.py`: дефолтный промпт чата (роль Айрис, короткие ответы, пригодные для озвучки, русский, без markdown и эмодзи) и отдельный промпт NLU. Промпты лежат в ресурсах, загружаются с возможностью переопределения пользователем, сборка итогового промпта из шаблона и подстановок доступна для предпросмотра в задаче 64.
3. NLU через LLM: компактное описание доступных команд и действий (имя, триггеры, слоты и их типы) из реестра действий (19) и БД команд, с бюджетом токенов и отбором по релевантности вместо выгрузки всего списка. Ответ строго JSON `{command, params, confidence}` — парсинг, валидация по схеме, один уточняющий ретрай на невалидный ответ, затем честное «не поняла» с записью в лог, а не выполнение мусора.
4. `nlu/llm/memory.py`: история диалога с настраиваемой длиной в сообщениях и токенах, суммаризация вытесняемых сообщений отдельным дешёвым вызовом, персистентность по профилю в БД, учёт лимита контекста модели, сброс по «Айрис, забудь» и по таймауту сессии.
5. `nlu/llm/tools.py`: маппинг реестра действий в `ToolSpec`, tool calling там, где провайдер его поддерживает, фоллбек на JSON-режим там, где нет. Выполнение только через реестр — с теми же проверками прав и подтверждениями опасных команд (39, 40); результат действия возвращается в диалог, чтобы модель могла его озвучить.
6. Мгновенные ответы: погода, валюта, время, факты маршрутизируются в действия из задачи 25 до обращения к модели, чтобы числа и даты не выдумывались. Правило маршрутизации описано в одном месте и покрыто тестами.
7. Тесты: матрица трёх режимов на текстовом входе, промах NLU → уход в LLM, невалидный JSON от модели, переполнение истории с суммаризацией, вызов действия через tool call на моке клиента, перехват «сколько времени» действием, а не моделью.

## Осторожно
- Модель нельзя пускать к действиям в обход реестра: подтверждения и права администратора обязательны и для tool call.
- Описание команд в промпте легко раздувается до всего контекста — держать бюджет и обрезать осознанно.
- LLM возвращает JSON в markdown-заборе и с лишним текстом: парсер должен это переживать, но не «догадываться» о смысле.
- В `ai_only` пользователь остаётся без заготовленных команд — предупредить об этом в UI задачи 64.
- Ни один тест не обращается к настоящей модели: клиент подменяется моком с заранее записанными ответами, включая заведомо кривые. Живой вызов сделал бы результат теста зависимым от версии модели и от квоты, а падение выглядело бы как баг в парсере.
- Тесты, требующие живого ключа или локальной модели, помечаются `@pytest.mark.hardware` и в CI не идут; Windows-специфичные части закрываются `pytest.mark.skipif(sys.platform != "win32")`, чтобы прогон в песочнице оставался зелёным.

## Готово когда
- [ ] Три режима переключаются на лету и ведут себя по-разному на одном и том же входе.
- [ ] В гибриде совпавшая команда выполняется без обращения к LLM, несовпавшая уходит в модель.
- [ ] Парсер и валидация переживают любой ответ модели: невалидный JSON не приводит к случайному действию.
- [ ] NLU-промпт стабильно даёт валидный вызов команды на настоящей модели — **проверяешь ты руками**: десяток живых фраз через свой ключ, чтобы увидеть, где промпт плывёт.
- [ ] История ограничивается и суммаризируется, не упираясь в лимит контекста, и переживает перезапуск.
- [ ] «Сколько времени» и «какая погода» отвечаются действиями, а не выдумкой модели.
- [ ] Тесты на моках зелёные, ruff, black и mypy strict проходят.
