# Задача 62 — Локальные LLM

**Этап:** H — LLM | **Зависит от:** 61 | **Разделы ТЗ:** 5.3

## Цель
Локальные модели через Ollama, LM Studio и llama.cpp за той же абстракцией `LLMClient`, с каталогом рекомендованных моделей, контролем памяти и автофоллбеком облако↔локально.

## Что сделать
1. `nlu/llm/ollama_client.py`: host/port из настроек, список установленных моделей с сервера (`/api/tags`), стриминг чата (`/api/chat`), `pull` модели с прогрессом в событиях для UI, управление `keep_alive`.
2. `nlu/llm/lmstudio_client.py`: OpenAI-совместимый endpoint — переиспользовать клиент из задачи 61 с другим `base_url` и без ключа, список моделей через `/v1/models`, а не хардкодом.
3. `nlu/llm/llamacpp_client.py`: прямой `llama-cpp-python` как опциональный путь — файл `.gguf` из менеджера моделей (14), `n_ctx`, `n_threads`, `n_gpu_layers` из конфига. Зависимость опциональная: если не установлена, движок просто недоступен с понятным объяснением, а не падением импорта.
4. `nlu/llm/catalog.py` + `resources/models/llm.json`: каталог рекомендованных моделей — Phi-3-mini 3.8B, Qwen2.5 1.5B–7B, Llama-3.2 1B–3B, Gemma 2 2B–9B. На каждую: тег Ollama, размер файла, квантизация, требования RAM/VRAM, назначение (чат / NLU / слабое железо). Расчёт вердикта «влезет / влезет впритык / не влезет» по фактической памяти машины.
5. Доступность и ресурсы: пинг сервера перед запросом с ясным сообщением «Ollama не запущена по адресу ...» и подсказкой, как поднять; отказ грузить модель крупнее лимита RAM из настроек (раздел 12) с объяснением; выгрузка модели после настраиваемого простоя; учёт режима экономии — при облачном провайдере локальный движок не держит память.
6. `nlu/llm/router.py`: режимы Online / Offline / Auto по образцу STT-роутера из задачи 11. В Auto — фоллбек на локальную модель при недоступности облака и обратно при восстановлении, с гистерезисом и кулдауном, чтобы не метаться, и уведомлением в UI при каждом переключении.
7. Тесты: моки HTTP Ollama и LM Studio (список моделей, стрим, pull с прогрессом, сервер недоступен), вердикты каталога на разных объёмах RAM, переключение роутера при падении облака и возврат назад.

## Файлы
`src/ayris/nlu/llm/ollama_client.py`, `lmstudio_client.py`, `llamacpp_client.py`, `catalog.py`, `router.py`, `resources/models/llm.json`, `tests/unit/test_llm_local.py`

## Осторожно
- Первый ответ локальной модели медленный из-за загрузки в память: показывать состояние «модель загружается», а не молча ждать.
- `llama-cpp-python` тянет нативные бинарники и ломает сборку Nuitka — держать импорт ленивым и локализованным в одном файле.
- Не дублировать код OpenAI-клиента ради LM Studio: различия только в базовом URL и авторизации.

## Готово когда
- [ ] Список моделей приходит с реально запущенного сервера, выбранная модель отвечает стримом.
- [ ] Выключенная Ollama даёт понятное сообщение за доли секунды, без долгих зависаний.
- [ ] Каталог честно отмечает модели, которые не влезут в память машины.
- [ ] Модель выгружается после простоя, RAM освобождается.
- [ ] В режиме Auto падение облака переключает на локальную модель без потери запроса пользователя.
- [ ] Тесты на моках зелёные, mypy strict проходит.
