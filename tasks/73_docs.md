# Задача 73 — Документация MkDocs

**Этап:** I — Плагины, сборка, релиз | **Зависит от:** 72 | **Разделы ТЗ:** 19

## Цель
Документация на MkDocs с Material-темой, покрывающая установку, настройку, создание команд, плагины и справочники, с автогенерацией того, что иначе разойдётся с кодом.

## Что сделать
1. `mkdocs.yml`: Material-тема в тёмно-фиолетовой палитре под стиль приложения, русская локализация, поиск, навигация по разделам: Установка, Быстрый старт, Настройка (по вкладкам), Команды и макросы, Справочник блоков действий, Плагины и API SDK, Импорт из VoiceAttack, FAQ, Устранение неполадок.
2. Пользовательские разделы: Установка (инсталлер, portable, требования, SmartScreen), Быстрый старт (первый запуск, онбординг, скачивание моделей, первые три команды), Настройка — по одной странице на вкладку настроек с описанием каждого параметра и разумных значений, а не пересказом подписей.
3. Команды и макросы: создание команды с нуля, триггеры (голос, regex, хоткей, событие, расписание), слоты, переменные и области видимости, логика If/While/Call, звуковое сопровождение, отладчик, hot reload. Не меньше пяти разобранных сквозных примеров, включая те, что идут в стартовом профиле «Примеры команд».
4. `docs/gen/actions_reference.py`: автогенерация справочника блоков действий из реестра действий (19) — категория, имя, параметры со типами и значениями по умолчанию, права, пример вызова в `.ayris`. Генерация при сборке документации, а не вручную.
5. `docs/gen/sdk_reference.py`: автогенерация справочника SDK из docstring'ов задачи 66 — методы, сигнатуры, разрешения, требуемые для каждого вызова, примеры. Раздел про плагины дополняется рукописной частью: структура манифеста, жизненный цикл, песочница, публикация плагина.
6. Импорт из VoiceAttack и AHK: что поддерживается, таблица соответствия действий, что не переносится и почему, порядок действий после импорта. Плюс FAQ и Устранение неполадок по реальным сценариям отказа из задачи 69 (не слышит, не запускается, модель не качается, хоткей не работает в игре, Ollama недоступна).
7. Скриншоты интерфейса: единый способ съёмки (фиксированный размер окна, тёмная тема, чистый профиль), папка `docs/assets/`, скрипт или инструкция для перевыпуска скриншотов после изменений UI, чтобы картинки не устаревали молча.
8. Сборка документации в CI: `mkdocs build --strict` в отдельной джобе (битые ссылки и отсутствующие страницы валят сборку), публикация артефакта, готовность к деплою на GitHub Pages. Ссылка на документацию из `README.md` и из UI (кнопка «Документация»).

## Осторожно
- Всё, что можно сгенерировать из кода, генерируется: рукописные списки действий и методов SDK устаревают к следующему коммиту.
- Документация на русском (как и UI), названия параметров и идентификаторы — в оригинальном написании, без перевода.
- `--strict` в CI отловит битые ссылки только если документы включены в навигацию: следить, чтобы новые страницы попадали в `mkdocs.yml`.
- Скриншоты с реальными данными профиля могут содержать личное: снимать на чистом профиле.
- Скриншоты — единственная часть документации, которую нельзя получить автоматически: на раннере нет живого рабочего стола. Значит, инструкция по перевыпуску должна быть настолько точной, чтобы человек повторил её через полгода и получил те же кадры.
- Генераторы справочников бегут в Linux-джобе и не должны тянуть модули с WinAPI: реестр действий читается через метаданные, а не импортом всего приложения, иначе `mkdocs build` упадёт на импорте там, где Windows нет.
- Если mkdocs и тема попадают в `requirements-ci.txt`, версии обязаны совпадать с `pyproject.toml` — за расхождением следит `tests/unit/test_packaging.py`.

## Готово когда
- [ ] `mkdocs build --strict` проходит без предупреждений, все разделы навигации на месте.
- [ ] Справочники действий и SDK генерируются из кода и совпадают с реальным API.
- [ ] Разделы настроек описывают все вкладки, примеры команд воспроизводимы копированием.
- [ ] FAQ и устранение неполадок покрывают сценарии отказа из задачи 69.
- [ ] Документация собирается в CI, ссылка есть в README и в интерфейсе; ruff, black и mypy на скриптах генерации проходят.
- [ ] Быстрый старт доводит нового пользователя от установки до первой сработавшей команды — **проверяешь ты руками**: пройти по своей же инструкции на чистой машине и записать, где спотыкаешься.
- [ ] Скриншоты интерфейса сняты единым способом и лежат в `docs/assets/` — **проверяешь ты руками**: нужен живой рабочий стол с открытым приложением.
