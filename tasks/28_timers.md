# Задача 28 — Таймеры, напоминания, будильники

**Этап:** D — Системные действия | **Зависит от:** 03, 19 | **Разделы ТЗ:** 6 (Таймеры), 20 этап 2

## Цель
Планировщик отложенных событий поверх таблицы `timers`: разовые таймеры, напоминания на дату/время, будильники и повторяющиеся по cron, с голосовым созданием и срабатыванием через тост, звук и TTS.

## Что сделать
1. `actions/timers/scheduler.py` — `TimerScheduler`: единый планировщик поверх репозитория `timers` (задача 03). Хранит только запись в БД, в памяти держит ближайшее срабатывание и один таймер ожидания (не поток на каждую запись). Пересчёт ближайшего события при добавлении/отмене/изменении, потокобезопасность, публикация `TimerFired` в event bus.
2. Типы записей: `timer` (относительный интервал — «через 5 минут»), `reminder` (абсолютные дата и время с текстом), `alarm` (время суток, опционально дни недели), `cron` (повторяющееся выражение). Вычисление следующего срабатывания в одном месте, работа в локальной таймзоне с корректным поведением при переводе часов и смене таймзоны системы.
3. Голосовое создание: разбор слотов времени в `nlu/slots.py` — относительные («через 10 минут», «через полтора часа»), абсолютные («в 7 утра», «завтра в 9», «в понедельник в 8»), повторяющиеся («каждый день в 7»), с русскими числительными и падежами. Действия `SetTimer`, `SetReminder`, `SetAlarm` принимают уже разобранное время, парсинг — на стороне слотов, не внутри действий.
4. Срабатывание: тост-уведомление Windows (`winrt` Toast с кнопками «Отложить» и «Отклонить», фоллбек на своё окно/`ToastNotify`), проигрывание звука из библиотеки или пользовательского файла, озвучивание текста через TTS. Повтор («отложить на N минут») создаёт новую запись; выполненные разовые записи помечаются, а не удаляются, — для истории.
5. Переживание рестарта: при старте приложения планировщик поднимает активные записи из БД и обрабатывает пропущенные срабатывания по политике из конфига (сработать сразу / сработать с пометкой «пропущено» / пропустить, если старше N минут); для cron-записей пересчитывается следующее время без лавины пропущенных срабатываний.
6. Управление: действия `CancelTimer` (по id или по описанию — «отмени таймер на пять минут»), `ListTimers` (типизированный список активных с оставшимся временем), редактирование записи; API для UI списка активных таймеров в расширенном оверлее и вкладке.
7. `actions/timers/sync.py` — опциональный отдельный модуль синхронизации с MS To Do, Google Calendar и CalDAV: общий ABC `CalendarSync`, ленивая загрузка зависимостей, выключено по умолчанию, недоступность провайдера не влияет на локальные таймеры.
8. Тесты: расчёт следующего срабатывания для всех типов (включая cron, дни недели, перевод часов), обработка пропущенных срабатываний при старте по каждой политике, отмена и редактирование, отсутствие дрейфа при длительной работе (мок часов, без реальных ожиданий), парсинг фраз времени.

## Осторожно
- `time.sleep` на длинный интервал не переживает сон системы: после пробуждения таймер «догоняет» — пересчитывать по абсолютному времени (`datetime`), а не по отсчёту интервала.
- Компьютер в спящем режиме не разбудится сам; будильник может опоздать — обрабатывать как пропущенное срабатывание и говорить об этом честно.
- Cron с DST даёт пропуск или дубль срабатывания на границе перевода — использовать `zoneinfo` и покрыть тестом.
- Toast-уведомления требуют зарегистрированного AppUserModelID, иначе не отображаются в Windows 11.
- Не создавать поток или `QTimer` на каждую запись — при десятках напоминаний это течёт.
- Почти вся задача — чистая логика и БД, она полностью проверяется в песочнице с мокнутыми часами. Наружу торчит только показ уведомления: тост через `winrt`, звук и TTS вынести за один интерфейс нотификатора, а планировщик пусть публикует `TimerFired`. Тогда тест на фейковом нотификаторе ловит, что событие пришло ровно один раз и с нужным текстом, без реальных ожиданий. На windows-раннере отдельный тест отправляет настоящий тост и убеждается, что вызов с зарегистрированным AppUserModelID не бросает исключение (`pytest.mark.skipif(sys.platform != "win32")`); увидеть тост и услышать звук там нечем — динамиков у раннера нет.
- Тесты, которым нужен звук, голос или видимое на экране уведомление, помечать `@pytest.mark.hardware` — в CI они не идут. Реальных `sleep` в тестах не должно быть вовсе: фиксированные часы и ручное продвижение времени, иначе прогон станет медленным и начнёт плавать на загруженном раннере.

## Готово когда
- [ ] «поставь таймер на 5 минут» создаёт запись, по срабатыванию приходит тост, звук и озвучивание. — **проверяешь ты руками**: расчёт времени закрыт тестами, а тост, звук и голос надо увидеть и услышать
- [ ] «напомни завтра в 9 позвонить» и «каждый день в 7 разбуди» планируются на правильное время.
- [ ] `ListTimers` показывает активные записи с оставшимся временем, `CancelTimer` отменяет по описанию.
- [ ] После перезапуска приложения таймеры не теряются, пропущенные обрабатываются по настроенной политике.
- [ ] Синхронизация календарей выключена по умолчанию и её отсутствие ничего не ломает.
- [ ] Тесты на расчёте времени, cron и пропущенных срабатываниях зелёные, ruff, black и mypy проходят.
