# Задача 25 — Браузер, поиск, мгновенные ответы

**Этап:** D — Системные действия | **Зависит от:** 19 | **Разделы ТЗ:** 6 (Браузер), 20 этап 3

## Цель
Открытие ссылок и поисковых запросов в браузере плюс мгновенные ответы (погода, курс валют, время в городе, короткие факты) с озвучиванием результата.

## Что сделать
1. `actions/system/browser.py`: действие `OpenURL` — открытие в браузере по умолчанию через `ShellExecuteW`, либо в конкретном браузере по имени (`chrome`, `firefox`, `edge`, `yandex`) с резолвом пути через индекс приложений из задачи 20; параметры «новое окно», «приватное окно», профиль браузера. Валидация и нормализация URL (схема по умолчанию `https://`, отказ на схемах `file:`/`javascript:` без явного флага).
2. Действие `SearchWeb`: провайдеры Google, Yandex, YouTube, DuckDuckGo, Wikipedia. Шаблоны URL живут в конфиге (`[actions.browser.providers]`, вида `yandex = "https://yandex.ru/search/?text={query}"`), а не в коде — пользователь может добавить свой; корректное URL-экранирование запроса, провайдер по умолчанию настраивается, распознавание провайдера прямо во фразе («найди в ютубе ...»).
3. `actions/system/instant.py`: мгновенные ответы через httpx — погода (Open-Meteo, без ключа; геокодинг названия города), курс валют (ЦБ РФ / exchangerate-like API), текущее время в городе по таймзоне, короткий факт/определение (Wikipedia summary API). Каждый провайдер — отдельный класс с общим интерфейсом `fetch(query) -> InstantAnswer`, добавление провайдера не требует правок вызывающего кода.
4. Действие `InstantAnswer`: определение типа запроса (погода/валюта/время/факт) по слотам NLU или явному параметру, вызов провайдера, форматирование короткого русского ответа для TTS (`message_ru`) плюс полные данные в типизированном `value` для UI. Кэш ответов с TTL по типу (погода ~10 мин, курс ~1 час, факт ~сутки) в БД или на диске, чтобы не дёргать API на каждый повтор.
5. Обработка отсутствия интернета: проверка онлайн-статуса из `core/state.py` (задача 04) до запроса, таймауты и ретраи с backoff, при неудаче — выдача просроченного кэша с оговоркой («данные за ...») либо понятная ошибка «Нет интернета». Никаких фоновых запросов без действия пользователя — zero telemetry.
6. Регистрация действий в реестре с типизированными параметрами; ключи API (если провайдер их требует) — только из keyring, помечены секретными.
7. Тесты: сборка URL по шаблонам провайдеров и экранирование запроса (кириллица, пробелы, спецсимволы), нормализация и отклонение опасных URL, парсинг ответов API на записанных фикстурах, логика TTL-кэша, поведение офлайн и при таймауте (моки httpx).

## Осторожно
- Не парсить HTML выдачи поисковиков — это ломается и нарушает их ToS; только официальные/публичные API и открытие ссылки в браузере.
- Аргументы командной строки браузеров различаются (`--incognito` у Chrome, `-private-window` у Firefox) — таблица флагов на провайдера, не общий хардкод.
- Тесты не должны ходить в сеть: только записанные фикстуры и моки.
- Учитывать лимиты публичных API — кэш обязателен, иначе на повторяющихся командах пойдут 429.

## Готово когда
- [ ] «открой ютуб», «найди в гугле погоду», «найди в ютубе ...» открывают правильные URL в нужном браузере.
- [ ] Провайдер поиска по умолчанию меняется в конфиге, свой провайдер добавляется шаблоном без правок кода.
- [ ] «какая погода», «курс доллара», «сколько времени в Токио» дают короткий озвученный ответ.
- [ ] Повторный запрос в пределах TTL берётся из кэша без обращения к сети.
- [ ] Офлайн выдаёт кэш с оговоркой или понятное сообщение, без трейсбека.
- [ ] Тесты на фикстурах зелёные, сеть в тестах не используется.
