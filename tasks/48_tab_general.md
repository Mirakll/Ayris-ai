# Задача 48 — Вкладка Общие

**Этап:** G — Интерфейс | **Зависит от:** 43, 44 | **Разделы ТЗ:** 8.1 (вкладка 1), 12

## Цель
Первая вкладка настроек: язык, тема, поведение при старте и закрытии, а также ресурсные ограничения — приоритеты процессов, лимит RAM, пулы потоков, режим экономии.

## Что сделать
1. Секция «Интерфейс»: язык — только русский, поле заблокировано с пояснением «Другие языки пока не поддерживаются»; тема — тёмная фиолетовая / светлая / следовать системной с мгновенным применением через API задачи 42 (без перезапуска и без подтверждения).
2. Секция «Запуск и закрытие»: автозапуск с Windows (через `utils/autostart.py` из задачи 44, состояние читается из реестра), старт свёрнутым в трей, поведение при закрытии окна — свернуть в трей / выйти из приложения. Все три — карточки настройки с подписями-пояснениями.
3. Секция «Производительность»: приоритет процесса помощника и отдельно аудио-воркера (Низкий / Нормальный / Высокий / Реальное время) с предупреждением на «Реальное время»; лимит RAM для локальных моделей (2 ГБ / 4 ГБ / 8 ГБ / без лимита); размеры пулов потоков — STT (1–4), TTS (1–2), LLM (1–2), макросы (1–4) слайдерами с числовым полем.
4. Режим экономии: тумблер «Не запускать локальные воркеры при онлайн-движках» с пояснением, что именно произойдёт (какие воркеры не поднимутся при текущем выборе движков), и предупреждением, что офлайн-фоллбек в этом режиме будет недоступен без задержки на старт.
5. Применение изменений: приоритеты и пулы применяются на лету через `WorkerManager` (задача 05), для настроек, требующих перезапуска воркера, — явная плашка «Применится после перезапуска воркера» и кнопка перезапуска прямо в карточке.
6. Панель ресурсов: текущее потребление RAM и CPU приложением и по воркерам отдельно, обновление раз в 1–2 секунды только когда вкладка видна, подсветка превышения заданного лимита RAM.

## Осторожно
- Состояние автозапуска показывать по факту реестра: пользователь мог убрать его сторонним менеджером автозагрузки.
- Приоритет «Реальное время» может подвесить систему на слабой машине — предупреждать в диалоге подтверждения, а не только подписью.
- Опрос RAM/CPU не должен работать в фоне при закрытой вкладке.
- Изменение пулов потоков — не повод пересоздавать воркеры без нужды; менять только затронутые.
- Тесты вкладки идут через pytest-qt в offscreen-режиме: они проверяют, что вкладка собирается без исключений, что выбор приоритета и слайдеры пулов доезжают до конфига и что опрос ресурсов останавливается при скрытии — но не то, как вкладка выглядит. Каждый созданный виджет закрывать в фикстуре: незакрытое окно настроек заставляет прогон в CI висеть до таймаута без внятной ошибки.

## Готово когда
- [ ] Смена темы применяется мгновенно ко всем открытым окнам, включая оверлей — **проверяешь ты руками**: глянуть, что тёмная и светлая читаются, ничего не осталось в старых цветах.
- [ ] Автозапуск и старт свёрнутым реально работают после перезагрузки Windows — **проверяет CI на windows-раннере** в части чтения и записи ключа реестра; фактический старт после ребута — **проверяешь ты руками**.
- [ ] Приоритеты и размеры пулов сохраняются в конфиг и применяются к живым процессам: запись в конфиг и вызов `WorkerManager` закрываются offscreen-тестом, применение приоритета к реальному процессу — **проверяет CI на windows-раннере**.
- [ ] Режим экономии выключает запуск локальных воркеров при онлайн-движках и объясняет последствия.
- [ ] Панель ресурсов показывает правдоподобные значения и не работает при скрытой вкладке: остановка опроса при скрытии проверяется offscreen-тестом, правдоподобность цифр — **проверяет CI на windows-раннере**.
- [ ] Настройки, требующие перезапуска воркера, помечены плашкой с кнопкой перезапуска.
