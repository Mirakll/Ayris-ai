# Задача 14 — Менеджер моделей (бэкенд)

**Этап:** B — Аудио и речь | **Зависит от:** 02 | **Разделы ТЗ:** 3.3, 16.3

## Цель
Бэкенд загрузки и учёта моделей STT/TTS/Wake/LLM: каталог, докачка с проверкой SHA256, установка, регистрация в БД, выбор активной модели. UI — задача 50.

## Что сделать
1. Каталог моделей: `resources/models/*.json` — по файлу на вид (`stt.json`, `tts.json`, `wake.json`, `llm.json`). Запись: `id`, `name`, `kind` (stt/tts/wake/llm), `engine`, `url`, `size_bytes`, `sha256`, `description`, `language`, `archive` (zip/tar/none), `schema_version`. Загрузка и валидация каталога через pydantic-модели, понятная ошибка при битом JSON.
2. `models/downloader.py`: скачивание httpx-стримом с докачкой через `Range` (resume после обрыва), временный файл `.part` и атомарное переименование по завершении, отмена загрузки, лимит скорости не нужен. Колбэк прогресса `(model_id, downloaded, total, speed_bps, eta_s)` + публикация события для UI.
3. Проверка целостности: подсчёт SHA256 потоково во время записи, сверка с каталогом, при несовпадении — удаление файла и типизированная ошибка. Распаковка архивов (zip/tar) в каталог модели с защитой от path traversal и проверкой свободного места до начала загрузки.
4. `models/registry.py`: регистрация установленной модели в таблице `models` (id, kind, engine, версия, путь, размер на диске, sha256, дата установки, активна ли), выбор активной модели на вид/движок, публикация `ActiveModelChanged`, чтобы воркеры перезагрузили модель.
5. Удаление модели: снятие с активной, проверка, что она не используется прямо сейчас, удаление файлов, чистка записи в БД. Подсчёт занятого места по видам моделей и суммарно — для UI и для кнопки «очистить кэш моделей» из раздела приватности.
6. Проверка целостности установленных моделей: пересчёт SHA256 (или быстрая проверка размера + опция полной верификации), отметка «повреждена» с предложением перекачать; определение отсутствующих на диске моделей, которые числятся в БД.
7. Тесты с локальным HTTP-сервером/мок-транспортом: успешная загрузка, обрыв и resume с догрузкой ровно недостающего хвоста, несовпадение SHA256, распаковка zip, попытка traversal, нехватка места, удаление модели, смена активной с событием.

## Файлы
`src/ayris/models/__init__.py`, `catalog.py`, `downloader.py`, `installer.py`, `registry.py`, `resources/models/stt.json`, `tts.json`, `wake.json`, `llm.json`, `tests/unit/test_model_manager.py`

## Осторожно
- Только бэкенд: никакого PySide6 в этих модулях, прогресс — через колбэк и event bus.
- Пути к моделям только через `core/paths.py`; профиль может лежать не в `%APPDATA%`.
- Resume безопасен только если сервер отдаёт `Accept-Ranges` и файл не изменился — сверять `ETag`/`Content-Length`, иначе качать заново.
- Загрузка идёт в фоне и не должна блокировать ни UI, ни аудио-пайплайн; параллельных загрузок одной модели быть не должно (блокировка по `model_id`).
- Модели весят гигабайты: SHA256 считать потоково, не читая файл в память.
- Если httpx к этому моменту ещё не попал в `requirements-ci.txt` (задача 11), пин `httpx==0.28.1` надо добавить туда той же версией, что в `pyproject.toml`: расхождение ловит `tests/unit/test_packaging.py`, а верхнеуровневый импорт пакета, которого нет в CI-наборе, красит сбор тестов целиком.
- Windows-специфика ловится только на раннере: занятый файл не удалить и не переименовать (`os.replace` даёт WinError 32), в архиве могут прийти обратные слэши и абсолютные `C:\...`, а путь длиннее 260 символов упрётся в лимит. Такие тесты помечаются `pytest.mark.skipif(sys.platform != "win32")`, чтобы прогон в Linux-песочнице оставался зелёным.

## Готово когда
- [ ] Каталог из `resources/models/*.json` читается и валидируется, битая запись даёт понятную ошибку.
- [ ] Загрузка с оборванным соединением продолжается с места обрыва, а не с нуля.
- [ ] Модель с неверным SHA256 не устанавливается и не остаётся на диске.
- [ ] Установленная модель появляется в таблице `models`, выбор активной публикует `ActiveModelChanged`.
- [ ] Удаление модели чистит и файлы, и запись; подсчёт занятого места сходится с реальностью. — **проверяет CI на windows-раннере**, отдельным тестом на удаление файла, открытого другим дескриптором
- [ ] Проверка целостности находит повреждённую и отсутствующую модель.
- [ ] Реальная модель из каталога скачивается и встаёт на место. — **проверяешь ты руками**: нужна сеть и место на диске; мок-сервер не ловит расхождения с настоящим хостингом (редиректы, отсутствие `Accept-Ranges`)
