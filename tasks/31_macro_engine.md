# Задача 31 — Интерпретатор макросов

**Этап:** E — Макросы | **Зависит от:** 30 | **Разделы ТЗ:** 7.1, 14

## Цель
Исполнитель дерева блоков команды: контекст выполнения, вызов действий через реестр, отмена, кулдаун и приоритет, устойчивость к ошибкам блоков.

## Что сделать
1. `macros/context.py` — `ExecutionContext`: переменные всех scope (local — на запуск, profile и global — через репозиторий), слоты из NLU, `last_result` (результат предыдущего блока), метаданные запуска (источник триггера, время старта, id команды), стек вызовов `CallCommand`.
2. `macros/engine.py` — `MacroEngine.run(command, slots, trigger_source) -> ExecutionReport`: обход дерева блоков, вызов действий строго через `ActionRegistry.execute`, передача результата в контекст. Выполнение в отдельном потоке из пула (размер из настройки «Пул потоков: Макросы 1–4»), UI-поток не блокируется ни на одном шаге.
3. Отмена: `cancel(run_id)` и глобальная отмена по команде «Айрис, отмена» — кооперативная проверка флага между блоками и внутри ожиданий (`Wait`/`Sleep` просыпаются немедленно), корректный откат состояния и событие `MacroCancelled`.
4. Кулдаун и приоритет: повторный запуск команды раньше `cooldown_ms` игнорируется с логом и опциональным звуком; при одновременном срабатывании нескольких команд более высокий `priority` вытесняет или ставит в очередь текущую (политика в настройках), режим «одна команда за раз» против «параллельно».
5. Try/Catch и устойчивость (ТЗ 14): каждый блок обёрнут обработчиком, ошибка пишется в лог с путём до блока, дальше — по настройке блока `on_error` (`continue` / `stop`) и по блоку `Catch`, если он есть. Наружу летит типизированное исключение из `core/errors.py`, не голый `Exception`.
6. Защита от зацикливания: лимит глубины вложенности блоков и стека `CallCommand`, лимит итераций `While`/`For` и общий таймаут выполнения команды — при превышении команда останавливается с понятной ошибкой.
7. `ExecutionReport`: список шагов (путь до блока, тип, статус, `duration_ms`, сообщение), общее время, итог. Публикация событий `MacroStarted` / `MacroBlockFinished` / `MacroFinished` / `MacroFailed` в event bus — на них потом сядут отладчик (35) и DevTools (58).
8. Тесты: оба примера из раздела 22 ТЗ выполняются на замоканном реестре действий; отмена посреди `Wait`; кулдаун; вытеснение по приоритету; ошибка блока с `continue` и со `stop`; срабатывание защиты от бесконечного цикла.

## Файлы
`src/ayris/actions/macros/engine.py`, `context.py`, `report.py`, `errors.py`, `tests/unit/test_macro_engine.py`

## Осторожно
- Ни один блок не выполняется в UI-потоке; действия, которым нужен UI (тосты, оверлей), маршалятся через event bus.
- Переменные `global` и `profile` разделяются между параллельными запусками — нужна блокировка на запись, иначе гонки.
- Таймаут действия принадлежит реестру (задача 19); движок не должен дублировать его своим `sleep`-опросом.
- Тайминговые проверки (отмена за < 200 мс, кулдаун) на windows-раннере плавают: там медленнее стартует поток, а системный таймер по умолчанию тикает раз в ~15 мс. Брать запас или подменять источник времени, иначе тест краснеет через раз без всякой причины в коде.
- Тесты движка идут на замоканном реестре и потому целиком проходят в песочнице. Если понадобится прогнать команду с настоящим действием, такой тест помечается `@pytest.mark.hardware` и в CI не запускается.

## Готово когда
- [ ] Обе команды из раздела 22 ТЗ выполняются полностью, порядок блоков и ветвление `If` корректны.
- [ ] Долгая команда прерывается по `cancel` за < 200 мс, включая ожидание внутри `Wait`.
- [ ] Повторный вызов внутри кулдауна не выполняется, в логе есть причина.
- [ ] Ошибка одного блока не роняет всю цепочку при `on_error = continue` и останавливает её при `stop`.
- [ ] Бесконечный `While` останавливается лимитом итераций, а не зависанием приложения.
- [ ] `ExecutionReport` содержит тайминг каждого блока; тесты, ruff, black и mypy зелёные.
