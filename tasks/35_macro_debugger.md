# Задача 35 — Отладчик макросов

**Этап:** E — Макросы | **Зависит от:** 32 | **Разделы ТЗ:** 7.3, 15

## Цель
Backend-отладчик команд: пошаговое выполнение, точки останова, watch переменных, лог с таймингами, запуск с произвольного блока и подмена слотов без голоса. UI на этот API сядет в задачах 52/53.

## Что сделать
1. `macros/debugger.py` — `MacroDebugger` поверх движка задачи 31: сессия отладки (`start(command, slots)`), состояния `running` / `paused` / `finished`, команды `continue`, `step_over`, `step_into` (заходит внутрь `CallCommand`), `step_out`, `stop`. Движок ставится на паузу кооперативно между блоками, без остановки UI-потока.
2. Точки останова: `add_breakpoint(block_path)` / `remove` / `toggle`, включение и отключение без сброса сессии, условные точки (выражение через вычислитель задачи 32), хранение точек вместе с командой между сессиями.
3. Watch-панель: `get_variables()` — текущие значения всех переменных в области видимости с типом и scope, `last_result` предыдущего блока, стек `CallCommand`; отдельный список watch-выражений, вычисляемых на каждой паузе. Изменение значения переменной на паузе (`set_variable`) для проверки ветвлений.
4. Лог выполнения: пошаговая запись (путь до блока, тип, входные параметры после подстановки `{var}`, результат, `duration_ms`, ошибка) — переиспользовать `ExecutionReport` задачи 31, не заводить второй формат. Публикация событий `DebugPaused(block_path, state)`, `DebugStepFinished`, `DebugFinished` в event bus.
5. «Выполнить с этого блока»: `run_from(block_path)` — запуск с указанного блока при заданном стартовом состоянии переменных, с предупреждением, что предыдущие блоки не выполнялись; и `run_block(block_path)` для одиночного блока.
6. Подмена слотов: `slots_override` — словарь значений слотов (`{app}`, `{volume}`, ...) для запуска без голоса, чтобы протестировать команду из редактора. Сохранение последнего набора слотов вместе с сессией.
7. Сохранение последней сессии отладки: точки останова, watch-выражения, подменённые слоты и последний отчёт — в БД по `command_id`, восстановление при повторном открытии команды.
8. Тесты: пауза на точке останова в нужном блоке; `step_into` внутрь `CallCommand` и `step_out` обратно; условная точка срабатывает только при истинном условии; изменение переменной на паузе меняет ветку `If`; `run_from` стартует с указанного блока; сессия восстанавливается после перезапуска.

## Файлы
`src/ayris/actions/macros/debugger.py`, `src/ayris/actions/macros/debug_session.py`, `tests/unit/test_macro_debugger.py`

## Осторожно
- Отладчик — только API и события: никаких импортов PySide6, вся отрисовка в задачах 52/53.
- Пауза не должна держать блокировку на `global`/`profile` переменных, иначе остановка на breakpoint подвесит остальные команды.
- Действия с побочными эффектами (`PowerAction`, `RunShell`, удаление файлов) в отладке требуют явного подтверждения либо режима «сухой прогон» — не выключать компьютер при пошаговом проходе.

## Готово когда
- [ ] Пошаговое выполнение останавливается ровно на нужном блоке, `step_into`/`step_out` работают на `CallCommand`.
- [ ] Точка останова, включая условную, срабатывает корректно.
- [ ] Watch отдаёт актуальные значения переменных и стек вызовов на каждой паузе.
- [ ] Лог показывает параметры после подстановки, результат и время каждого блока.
- [ ] Команда запускается с произвольного блока и с подменёнными слотами, без голоса.
- [ ] Сессия отладки восстанавливается после перезапуска; тесты, ruff и mypy зелёные.
