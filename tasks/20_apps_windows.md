# Задача 20 — Программы и окна

**Этап:** D — Системные действия | **Зависит от:** 19 | **Разделы ТЗ:** 6 (Программы), 18

## Цель
Запуск приложений по имени и управление окнами: поиск в индексе установленных программ, фокус, состояние окна, привязка к краям, виртуальные рабочие столы.

## Что сделать
1. `actions/system/app_index.py`: индекс установленных приложений из четырёх источников — реестр (`Uninstall`, `App Paths`), ярлыки меню Пуск (`.lnk` в общем и пользовательском профилях), `PATH`, UWP-пакеты через `shell:AppsFolder`. Для каждой записи: отображаемое имя, исполняемый файл или AUMID, иконка, источник. Кэш индекса в БД или JSON с TTL и фоновым обновлением, ручной рефреш.
2. Резолвер слота `{app}`: сопоставление фразы с индексом — точное совпадение, нормализация (регистр, пробелы, кириллица/латиница), fuzzy по порогу из конфига, таблица псевдонимов (`хром`/`chrome`, `браузер`, `диспетчер задач`, `вс код`/`vscode`). При нескольких кандидатах — выбор по весу источника и частоте запусков, при неоднозначности — `ActionError` с вариантами для уточняющего вопроса.
3. `actions/system/apps.py`: запуск `.exe` с аргументами и рабочей папкой, `.lnk` через `ShellExecuteW`, UWP через `explorer.exe shell:AppsFolder\<AUMID>`. Закрытие приложения: сначала `WM_CLOSE` окнам процесса, по таймауту — завершение процесса (только с явным флагом `force`). Действия `RunApp`, `CloseApp`.
4. `actions/system/windows.py`: перечисление окон через `EnumWindows` (только видимые, с заголовком, без tool-window), поиск по заголовку (подстрока/regex), классу и имени процесса; фокус через `ShowWindow` + `SetForegroundWindow` с обходом ограничения переднего плана (`AttachThreadInput`/`ALT`-трюк); состояния minimize/maximize/restore; привязка к краям эмуляцией `Win+Left/Right` либо расчётом рабочей области монитора. Действия `FocusWindow`, `WindowState`, `ListWindows`.
5. `actions/system/desktops.py`: виртуальные рабочие столы через недокументированный COM `IVirtualDesktopManager` с версионной проверкой Windows и фоллбеком на эмуляцию `Win+Ctrl+Left/Right`; перечисление, переключение по номеру и относительно текущего. Действие `SwitchDesktop`.
6. Регистрация всех действий в реестре с типизированными параметрами и результатами (`ListWindows` возвращает список моделей окон, а не строки), понятные русские сообщения об ошибках («Не нашла приложение "..."»).
7. Тесты: резолвер имён на фикстуре индекса (кириллица, латиница, опечатки, псевдонимы, неоднозначность), парсинг записей реестра и `.lnk` на фикстурах, схемы параметров действий. Реальные запуск/фокус — интеграционные тесты с пометкой пропуска не на Windows.

## Осторожно
- `SetForegroundWindow` молча не работает без права переднего плана — нужен обходной путь и лог при неудаче, а не тихий провал.
- UWP запускается только через `shell:AppsFolder\<AUMID>`, прямой путь к exe не годится.
- API виртуальных столов не документирован и меняется между сборками Windows: изолировать в одном модуле, при несовместимости — фоллбек на хоткеи.
- Индексация меню Пуск и реестра медленная: только в фоне, не на UI-потоке.
- Не завершать процессы принудительно по умолчанию — риск потери данных пользователя.
- Держать `utils/winapi.py` тонким слоем над `EnumWindows`, `ShowWindow`, `SetForegroundWindow`, `ShellExecuteW`, а логику действий — отдельно. Тогда в песочнице проверяется, что действие передало вниз нужный hwnd и нужную константу (`SW_MINIMIZE`, а не `SW_HIDE`) и что при отсутствии окна возвращается `ActionError` с русским текстом; на windows-раннере те же действия гоняются по-настоящему — перечисление окон, запуск и закрытие `notepad.exe`, чтение реестра и меню Пуск там работают. Windows-специфичные тесты закрывать `pytest.mark.skipif(sys.platform != "win32")`, чтобы прогон в песочнице оставался зелёным.
- На раннере нет видимого рабочего стола, и `SetForegroundWindow` может вернуть ложь без ошибки. Автоматически проверяется только то, что неудача попала в результат и в лог; сам факт «окно вышло вперёд» подтверждается глазами.
