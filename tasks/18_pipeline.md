# Задача 18 — Пайплайн-диспетчер

**Этап:** C — NLU и пайплайн | **Зависит от:** 09, 11, 13, 17 | **Разделы ТЗ:** 5.1, 15, 18

## Цель
Центральный оркестратор всего цикла: wake word → запись фразы → STT → NLU → выбор режима → действие или LLM → TTS-ответ, с машиной состояний, отменой на любом шаге и детальным логом таймингов.

## Что сделать
1. `core/pipeline.py` — `Pipeline` как машина состояний: `Idle → Listening → Recording → Transcribing → Understanding → Executing → Responding → Idle`. Переходы явные, у каждого состояния свой таймаут из конфига, истечение таймаута — переход в `Idle` с логом и, где уместно, голосовым сообщением. Публикация `PipelineStateChanged(state, session_id)` — на это состояние завязана анимация сферы в оверлее (Idle/Listening/Thinking/Speaking/Error).
2. Сборка цикла на существующих компонентах: `WakeWordDetected` (задача 09) стартует сессию → сегментатор из задачи 08 отдаёт фрагмент фразы → `SttRouter.transcribe()` (задача 11) → нормализация, матчер и слоты (15, 16) с контекстом (17) → выбор пути по режиму NLU → выполнение → `say()` (задача 13). Пайплайн ничего не реализует сам, только оркеструет и владеет состоянием сессии.
3. Три режима из ТЗ 5.1: «только заготовленные команды» (нет совпадения — сообщить, что команда не найдена), «гибрид» (сначала матчер, при промахе — LLM), «только ИИ» (вся фраза уходит в LLM). Режим берётся из конфига и может меняться на лету.
4. Интеграция с LLM через интерфейс-заглушку: `nlu/llm/base.py` с ABC `LlmClient.complete(messages, tools) -> LlmResponse` и `NullLlmClient`, возвращающий понятное «ИИ не настроен». Реальные провайдеры — задача 63; пайплайн не должен меняться при их появлении.
5. Отмена на любом этапе: подписка на `CancelRequested` (задача 17) — прерывание записи, отмена STT-запроса, отмена выполнения действия, остановка TTS, возврат в `Idle` с корректной чисткой сессии. Barge-in: новая активация (wake word или PTT) во время озвучки прерывает текущий ответ и начинает новую сессию, не дожидаясь конца TTS.
6. Детальный лог пайплайна: `PipelineTrace(session_id)` со стадиями и длительностью каждой в мс (запись фразы, STT, NLU, действие, TTS), исходным текстом STT, выбранной командой и слотами, результатом. Вывод в лог по ТЗ 15 в формате `STT raw → NLU intent → Action → Result` с таймингами, структурированная выдача для вкладки DevTools, запись сессии в таблицу `history`.
7. Обработка ошибок каждой стадии: типизированные исключения из `core/errors.py` ловятся на границе стадии, пользователю уходит короткое голосовое сообщение по делу («не расслышала», «нет связи и офлайн-модель не установлена», «команда не найдена», «действие не выполнилось»), в лог — полная трассировка. Ошибка одной сессии не ломает пайплайн: возврат в `Idle` и готовность к следующей активации.
8. Точка входа для текстового ввода из DevTools: `run_text(text)` — тот же пайплайн, начиная со стадии NLU, минус wake word и STT; результат и трассировка возвращаются вызывающему. Используется и в тестах вместо аудио.
9. Тесты: полный проход с мок-STT/мок-действием/мок-TTS и проверкой последовательности состояний; все три режима NLU; отмена на каждой стадии; barge-in во время озвучки; таймаут стадии; ошибка каждой стадии даёт сообщение и возврат в `Idle`; `run_text` проходит пайплайн; трассировка содержит тайминги всех стадий и попадает в `history`.

## Осторожно
- Пайплайн живёт в main process и не должен блокировать UI-поток: все обращения к воркерам асинхронные, ожидание результата через future/сигналы, а не `.join()`.
- Одновременно активна одна сессия: новая активация либо отменяет текущую (barge-in), либо игнорируется — правило явное и покрыто тестом, а не «как получится».
- Barge-in требует, чтобы микрофон слушал во время озвучки: следить за эхом собственного TTS (не активироваться на своей же речи — учитывать состояние `Responding` и, при необходимости, гейт по устройству вывода).
- `session_id` протаскивать через все стадии и события, иначе в логе и в UI перепутаются параллельные попытки.
- Не тащить в пайплайн импорт конкретных движков: только роутеры и абстракции, иначе инвариант 4 из контекста нарушается.

## Готово когда
- [ ] Полный цикл от активации до озвучки проходит на моках, последовательность состояний соответствует машине.
- [ ] Все три режима NLU работают, «только ИИ» и «гибрид» с заглушкой LLM дают понятное сообщение о ненастроенном ИИ.
- [ ] Отмена срабатывает на любой стадии и возвращает пайплайн в `Idle` без утечек сессий.
- [ ] Новая активация во время озвучки прерывает ответ и запускает новую сессию.
- [ ] В логе видна строка `STT raw → NLU intent → Action → Result` с таймингами каждой стадии в мс, сессия записана в `history`.
- [ ] Ошибка любой стадии даёт голосовое сообщение и не выводит пайплайн из строя.
- [ ] `run_text("громкость 50")` из DevTools выполняет команду без аудио.
