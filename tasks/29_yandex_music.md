# Задача 29 — Яндекс Музыка

**Этап:** D — Системные действия | **Зависит от:** 19 | **Разделы ТЗ:** 6 (Яндекс Музыка), 7.2

## Цель
Управление воспроизведением: надёжный базовый уровень через системные медиа-контролы Windows (работает с любым плеером, включая браузер) и опциональный продвинутый уровень с поиском и плейлистами через браузер-автоматизацию.

## Что сделать
1. `actions/media/smtc.py`: работа с System Media Transport Controls через WinRT (`GlobalSystemMediaTransportControlsSessionManager`) — перечисление медиа-сессий, определение активной и выбор сессии по имени приложения (приоритет Яндекс Музыки из конфига, иначе текущая активная), чтение текущего трека (исполнитель, название, альбом, статус, позиция), команды play/pause/toggle, next, previous. Фоллбек на виртуальные медиа-клавиши (`VK_MEDIA_PLAY_PAUSE` и др.) через бэкенд ввода задачи 23, если сессия не найдена.
2. Действия базового уровня: `YMPlay`, `YMPause`, `YMNext`, `YMPrev`, `NowPlaying`. `NowPlaying` возвращает типизированный трек и короткую русскую фразу для озвучивания («Сейчас играет ... — ...»). Все они работают без авторизации и без интернет-зависимости от неофициальных API.
3. `YMLike`: SMTC не умеет лайк, поэтому — настраиваемый горячий ключ приложения Яндекс Музыки (по умолчанию комбинация из конфига) через фокус окна плеера и эмуляцию клавиш с возвратом фокуса на прежнее окно, либо через продвинутый уровень, если он включён. Честно сообщать, если плеер не найден.
4. `actions/media/yandex_music.py` — продвинутый уровень (опционально, выключен по умолчанию): Playwright с подключением к персистентному профилю браузера (пользователь авторизуется один раз сам, пароли приложение не запрашивает и не хранит). Действия `YMSearch` (поиск трека/исполнителя и запуск) и `YMPlaylist` (запуск плейлиста по имени из «Моей волны»/коллекции). Ленивая установка Playwright и браузера: при отсутствии — понятная ошибка с инструкцией (`playwright install chromium`), а не трейсбек при импорте.
5. Изоляция хрупкого кода: все селекторы и любые обращения к неофициальному API живут в одном модуле и в одной таблице селекторов (переопределяемой из конфига), чтобы при изменении вёрстки правился один файл. В README/докстринге модуля прямо предупредить, что продвинутый уровень неофициален и может сломаться в любой момент; базовый уровень при этом продолжает работать.
6. Регистрация всех действий в реестре с типизированными параметрами и результатами; продвинутые действия помечены как требующие опциональной зависимости и корректно исчезают/деградируют из списка блоков редактора, если она недоступна.
7. Тесты: выбор сессии из фикстуры списка сессий (плеер найден / не найден / несколько), парсинг метаданных трека и формирование фразы для TTS, фоллбек на медиа-клавиши, ошибка при отсутствии Playwright (мок импорта), таблица селекторов как данные. Реальный Playwright в CI не запускать.

## Осторожно
- Неофициальное API и вёрстка Яндекс Музыки могут измениться в любой момент: продвинутый уровень — best-effort, его поломка не должна ронять помощника.
- Playwright тянет ~300 МБ браузера — ставить только по явному согласию пользователя, не в основной набор зависимостей.
- WinRT-вызовы асинхронные: оборачивать корректно, не блокировать UI-поток ожиданием.
- Медиа-клавиши уходят в приложение, которое система считает активной медиа-сессией, — это не всегда нужный плеер; поэтому приоритет у явного выбора сессии.
- Не хранить и не запрашивать логин/пароль Яндекса — только персистентный профиль браузера, авторизацию пользователь делает сам.
- На раннере нет ни живого аккаунта, ни запущенного плеера, поэтому WinRT-менеджер сессий спрятать за интерфейс: выбор сессии, парсинг метаданных трека, фраза для TTS и фоллбек на медиа-клавиши проверяются на фикстурах списка сессий, включая пустой список и несколько плееров сразу. Фоллбек проверяется подменой бэкенда ввода из задачи 23 — тест смотрит, что ушёл именно `VK_MEDIA_PLAY_PAUSE`. На windows-раннере отдельный тест дергает настоящий `GlobalSystemMediaTransportControlsSessionManager` и убеждается, что при отсутствии плееров возвращается пустой список, а `NowPlaying` отвечает русской фразой «сейчас ничего не играет» вместо исключения (`pytest.mark.skipif(sys.platform != "win32")`). Всё, что требует запущенной Яндекс Музыки, авторизации или настоящего Playwright, помечать `@pytest.mark.hardware` — такие тесты в CI не запускаются.
- `playwright` пинить одной версией сразу в `pyproject.toml` и `requirements-ci.txt`, иначе краснеет `tests/unit/test_packaging.py`, который следит за расхождением. Но сам браузер в CI не нужен: если колесо с браузером на раннере не ставится, в `requirements-ci.txt` пакет не добавлять вовсе, а импорт делать отложенным внутри функции — иначе сбор тестов упадёт на импорте вместо понятной ошибки с инструкцией `playwright install chromium`.
- Если продвинутый уровень когда-нибудь начнёт получать токен или cookie сессии, они живут в Windows Credential Manager через `keyring` и не попадают ни в конфиг, ни в лог — в конфиге допустим только путь к профилю браузера. Действия, которые что-то ломают необратимо (чистка коллекции, удаление из плейлиста), помечать `is_dangerous=True` и пропускать через подтверждение из задачи 40; переключение трека и громкости подтверждения не требуют.

## Готово когда
- [ ] Play/Pause, Next, Prev управляют Яндекс Музыкой в приложении и в браузере через SMTC. — **проверяешь ты руками**: нужен живой аккаунт и запущенный плеер
- [ ] `NowPlaying` называет текущий трек, при отсутствии сессии — понятное сообщение. — **проверяешь ты руками**: назвать играющий трек можно только на своей машине, ветку «сессии нет» ловит CI на раннере
- [ ] Без найденной сессии команды уходят на медиа-клавиши и всё равно работают. — **проверяешь ты руками**: убедиться, что трек действительно переключился (сам факт отправки медиа-клавиши закрыт тестом)
- [ ] `YMLike` срабатывает и возвращает фокус на прежнее окно. — **проверяешь ты руками**: нужен аккаунт и окно плеера, лайк смотреть в самой Яндекс Музыке
- [ ] Без установленного Playwright базовые действия работают, продвинутые дают внятную инструкцию по установке.
- [ ] Весь неофициальный код и селекторы сосредоточены в одном модуле.
- [ ] Тесты зелёные, Playwright в тестах не запускается, ruff, black и mypy проходят.
