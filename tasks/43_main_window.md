# Задача 43 — Каркас главного окна

**Этап:** G — Интерфейс | **Зависит от:** 42, 02 | **Разделы ТЗ:** 8.1

## Цель
Окно настроек с боковой навигацией по 11 вкладкам и общий механизм привязки вкладок к конфигу. Сами вкладки — пустые плейсхолдеры, наполняются в задачах 48–59.

## Что сделать
1. `gui/main_window.py`: `QMainWindow` с боковой навигацией — список разделов слева, стек страниц справа. Разделы: Общие, Голос, Команды, ИИ / LLM, Горячие клавиши, Оверлей, Плагины, Профили, Обновления, Логи / DevTools, Приватность. Иконка и заголовок на каждый раздел, выделение активного.
2. Ленивая инициализация: страница создаётся при первом открытии раздела, а не на старте окна. Реестр вкладок (`gui/tabs/registry.py`) — соответствие раздела фабрике страницы, чтобы задачи 48–59 подключали свои вкладки одной записью.
3. `gui/tabs/base.py` — `SettingsTab`: базовый класс с двусторонней привязкой к конфигу — `load_from_config()` при показе, сохранение при изменении контрола (с дебаунсом, чтобы не писать TOML на каждое движение слайдера), реакция на внешнее событие `ConfigChanged` с обновлением полей без зацикливания (флаг «программное изменение»). Хелперы привязки для тумблера, слайдера, комбобокса, поля ввода.
4. Индикатор несохранённых изменений в заголовке секции и кнопка «Сбросить секцию к значениям по умолчанию» с диалогом подтверждения из задачи 42. Сброс берёт дефолты из pydantic-модели конфига, а не из отдельного списка.
5. Поиск по настройкам: индекс «название поля + подпись + раздел», поле поиска сверху, выбор результата открывает нужный раздел, прокручивает к полю и подсвечивает его на пару секунд. Регистрация полей в индексе — из `SettingsTab`, чтобы вкладки не дублировали логику.
6. Состояние окна: сохранение размера, позиции и последнего открытого раздела в конфиг, восстановление с проверкой, что окно попадает на существующий монитор. Закрытие окна = сворачивание в трей (поведение настраивается в задаче 48, по умолчанию — в трей), реальный выход — только через трей или явное действие.
7. Плейсхолдеры вкладок: для каждого раздела страница-заглушка на базе пустого состояния из задачи 42 с текстом «Раздел появится в задаче NN» — чтобы навигация была проверяема до наполнения.

## Файлы
`src/ayris/gui/main_window.py`, `src/ayris/gui/nav_sidebar.py`, `src/ayris/gui/tabs/__init__.py`, `base.py`, `registry.py`, `placeholder.py`, `src/ayris/gui/settings_search.py`, `tests/unit/test_settings_binding.py`

## Осторожно
- Ничего тяжёлого в конструкторе окна: инициализация вкладок ленивая, обращения к аудио-устройствам и моделям — из вкладок, а не из каркаса.
- Привязка к конфигу должна пережить внешнее изменение файла и не устроить эхо «UI → конфиг → UI».
- Позиция окна из конфига может указывать на отключённый монитор — проверять и центрировать по основному.

## Готово когда
- [ ] Окно открывается, все 11 разделов переключаются, страница создаётся только при первом открытии.
- [ ] Изменение контрола на тестовой вкладке пишется в `config.toml`, внешнее изменение конфига обновляет контрол.
- [ ] Кнопка сброса секции возвращает значения по умолчанию после подтверждения.
- [ ] Поиск находит поле по подписи и открывает раздел с подсветкой поля.
- [ ] Размер, позиция и последний раздел восстанавливаются после перезапуска; окно не уезжает за пределы экранов.
- [ ] Закрытие окна не завершает процесс приложения.
