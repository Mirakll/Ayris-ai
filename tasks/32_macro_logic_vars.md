# Задача 32 — Логика и переменные

**Этап:** E — Макросы | **Зависит от:** 31 | **Разделы ТЗ:** 7.1, 7.2

## Цель
Блоки управления потоком и подпрограмм, типизированные переменные со scope и персистентностью, безопасный вычислитель выражений и подстановки `{var}`.

## Что сделать
1. `macros/blocks/logic.py` — блоки потока: `If`/`Else`, `Switch` (список case + default), `While` (с лимитом итераций), `For` (по диапазону и по массиву), `Break`, `Continue`, `Return` (с возвращаемым значением), `Try`/`Catch`. Каждый блок реализует общий интерфейс исполнения и умеет отдавать сигнал управления потоком движку задачи 31.
2. `CallCommand`: вызов другой команды как подпрограммы — передача параметров в её локальный scope, возврат значения из `Return` в `last_result` вызывающего, изоляция локальных переменных, учёт лимита глубины стека и запрет циклов (проверка из задачи 30).
3. `macros/expressions.py` — движок выражений **без `eval`**: собственный токенизатор и парсер (или ограниченный обход `ast` с белым списком узлов). Поддержка: арифметика (`+ - * / // % **`), сравнения (`== != < <= > >=`), логика (`and or not`), индексация массивов и словарей, скобки, литералы, обращения к переменным и слотам. Явный набор разрешённых функций (`len`, `int`, `float`, `str`, `round`, `abs`, `min`, `max`, `contains`) — ничего сверх списка.
4. Подстановка `{var}` в строковые параметры блоков: рекурсивно по всем строковым полям `params`, экранирование `{{` / `}}`, понятная ошибка при неизвестном имени, форматирование чисел без «хвостов» вида `50.0` там, где ожидается целое.
5. `macros/blocks/variables.py` — блоки данных: `SetVar`, `GetVar`, `ArrayPush`, `ArrayGet`, `DictSet`, `DictGet` (плюс `ArrayPop`/`ArrayLength`/`DictKeys`, если бесплатно по коду). Типы: строка, int, float, bool, массив, словарь; приведение типов с явной ошибкой при несовместимости.
6. `macros/variables.py` — хранилище переменных: scope `local` (жизнь запуска), `profile` и `global` (через репозиторий задачи 03), флаг `persistent` — запись в таблицу `variables` при изменении, чтение при старте, потокобезопасность при параллельных запусках.
7. Тесты: каждая конструкция потока (включая вложенные циклы с `Break`/`Continue`), `CallCommand` с параметрами и возвратом, вычислитель на корректных и вредоносных выражениях (`__import__`, доступ к атрибутам, обращение к недоступным именам — всё должно отклоняться), подстановка `{var}`, персистентность переменной между запусками.

## Осторожно
- Никакого `eval`/`exec` даже «временно»: выражения приходят из импортированных чужих профилей VoiceAttack (задача 36) и из плагинов.
- Вычислитель должен быть защищён от разрастания (`10**10**10`), длинных строк и глубокой вложенности — лимиты на размер выражения и глубину дерева.
- `persistent`-переменные не писать в БД на каждой итерации цикла: батчить запись или писать по завершении блока.
- Здесь нет ни железа, ни окон — всё проверяется автоматически, включая переживание перезапуска: его тест изображает пересозданием репозитория поверх того же файла БД, а не настоящим рестартом процесса. Иначе такой тест не запустится ни в песочнице, ни в CI.

## Готово когда

- [ ] `CallCommand` передаёт параметры, возвращает значение и не видит локальные переменные вызывающего.
- [ ] Выражение `{work_monitor_brightness} > 0` из примера 2 ТЗ вычисляется корректно; попытка `__import__("os")` отклоняется.
- [ ] Все шесть блоков данных из таблицы 7.2 работают на всех заявленных типах.
- [ ] `persistent`-переменная переживает перезапуск приложения, `local` — нет.
- [ ] Тесты, ruff, black и mypy strict зелёные.
