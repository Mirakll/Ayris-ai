# Задача 54 — Hot reload и история версий

**Этап:** G — Интерфейс | **Зависит от:** 52 | **Разделы ТЗ:** 7.3, 18

## Цель
Изменённая команда начинает работать сразу после сохранения, а редактор даёт undo/redo, историю версий с diff и откатом, автосохранение черновика и защиту от потери правок.

## Что сделать
1. `actions/macros/hot_reload.py` — применение сохранённой команды без рестарта: перерегистрация триггеров типа `hotkey` через задачу 37, перестройка индекса NLU для голосовых фраз (задачи 15, 38), пересоздание расписаний и подписок на события, снятие всего перечисленного при выключении или удалении команды. Публикация `CommandReloaded(command_id)` в event bus; подписчики (дерево задачи 51, оверлей) обновляются по событию. Точечная перерегистрация одной команды, а не полная перезагрузка профиля.
2. Порядок применения при сохранении: валидация задачи 30 → запись в БД в одной транзакции → создание версии → перерегистрация триггеров → событие. Ошибка на любом шаге откатывает транзакцию и оставляет работать предыдущую зарегистрированную версию, а не выключает команду.
3. Undo/redo в редакторе (`gui/widgets/editor_undo.py`): стек операций с русским описанием каждой («Добавлен блок Say», «Изменён параметр level», «Перемещён блок»), горячие клавиши Ctrl+Z / Ctrl+Shift+Z, выпадающий список последних операций, объединение мелких правок одного поля в одну операцию по таймауту. Стек общий для списочного и нодового режимов, сбрасывается при смене команды.
4. История версий (`gui/widgets/version_history.py`): таблица версий из `command_versions` (номер, дата, автор изменения — пользователь или импорт, краткое описание правки, размер), запись версии при каждом сохранении с ограничением количества и вытеснением самых старых, ручная пометка версии как важной (не вытесняется).
5. Просмотр diff между версиями (`actions/macros/diff.py`): структурное сравнение двух `CommandModel` по блокам, триггерам, переменным и звукам с выдачей списка изменений (добавлено / удалено / изменено, с путём до блока и старым и новым значением), показ рядом с деревом версий. Diff считается на модели, а не на тексте JSON.
6. Откат к версии: предпросмотр изменений до применения, применение как обычное сохранение (то есть с новой версией в истории, без потери текущего состояния), подтверждение через диалог задачи 42. Экспорт выбранной версии в `.ayris` через сериализатор задачи 30.
7. Автосохранение черновика: несохранённые правки пишутся в отдельное хранилище черновиков по `command_id` с интервалом из конфига, при следующем открытии команды предлагается восстановить черновик или отбросить. Черновик удаляется после успешного сохранения.
8. Защита от потери правок: при переключении команды, смене вкладки, смене профиля и закрытии приложения — диалог «Сохранить / Не сохранять / Отмена» с перечислением, что именно изменено; индикатор несохранённых изменений в заголовке редактора и у узла в дереве.
9. Тесты: сохранение команды перерегистрирует хоткей и обновляет индекс NLU без рестарта; ошибка валидации оставляет активной прежнюю версию; undo/redo восстанавливает модель по шагам; diff находит добавленный, удалённый и изменённый блок с верным путём; откат создаёт новую версию; черновик восстанавливается после аварийного завершения.

## Осторожно
- Перерегистрация триггеров должна быть идемпотентной: двойное сохранение не оставляет двух подписок на одну фразу и не приводит к двойному запуску команды.
- Команда может выполняться в момент сохранения: применять новую версию к уже запущенному экземпляру нельзя, он доигрывает старую — правило явное и покрыто тестом.
- `command_versions` растёт быстро: без лимита и вытеснения БД распухнет, но помеченные важными версии не удаляются.
- Автосохранение черновиков не должно писать в БД на каждое нажатие клавиши и не должно попадать в экспорт профиля.

## Готово когда
- [ ] Правка команды применяется сразу после сохранения: хоткей и голосовая фраза работают в новой версии без рестарта.
- [ ] Ошибка валидации или записи не ломает уже зарегистрированную команду.
- [ ] Undo/redo проходит по стеку с понятными русскими описаниями операций в обоих режимах редактора.
- [ ] Версии пишутся в `command_versions`, diff показывает изменения с путём до блока, откат создаёт новую версию.
- [ ] Экспорт выбранной версии в `.ayris` работает.
- [ ] Несохранённые правки восстанавливаются из черновика, уход из редактора спрашивает подтверждение.
- [ ] Тесты, ruff и mypy зелёные.
