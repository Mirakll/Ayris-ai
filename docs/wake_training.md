# Обучение слова активации «Айрис» (openWakeWord)

Рецепт, как с нуля обучить `айрис.onnx` — дефолтную фразу активации Ayris «из
коробки» (Задача 60a). Обучение — **внешний по отношению к приложению шаг**: оно
не запускается из Ayris, не входит в его зависимости и не в CI. Артефакт —
единственный `.onnx`, который приложение лишь подхватывает (см. ниже «Интеграция»).

Это НЕ распознавание речи. Обучается только ступень «wake», которая ловит слово
«Айрис» и будит ассистента. Распознавание самой команды после пробуждения — GigaAM
(STT), отдельная модель, `айрис.onnx` её не заменяет и не конфликтует с ней.

## Почему рабочая папка на D:

Нативные аудио-либы (espeak внутри Piper, часть кода openWakeWord) не открывают
пути с кириллицей — репозиторий лежит на `E:\мистер бит ест рис`. Поэтому всё
обучение идёт в `D:\ayris-wake-train\` (ASCII-путь), а готовый `.onnx` копируется
в репозиторий в самом конце.

## Железо (проверено на этой машине)

- GPU: NVIDIA RTX 2060, 6 ГБ — достаточно (обучается лёгкая голова поверх общих
  эмбеддингов, `auto_reduce_batch_size` спасает синтез от OOM).
- Диск: D: ~265 ГБ свободно. Наборы данных — десятки ГБ.
- Python **3.11** (не 3.14: нет колёс torch/openwakeword). venv отдельный.

## Пайплайн (не изобретаем обучение заново)

Используется **официальный драйвер openWakeWord** (`openwakeword/train.py`) со
стадиями `--generate_clips --augment_clips --train_model`. Наши скрипты в
`D:\ayris-wake-train\` — тонкие обёртки, которые собирают его training-config под
каждый раунд и гоняют автоцикл до мягких критериев:

| Файл | Что делает |
|------|-----------|
| `setup.ps1` | venv (py3.11) + torch(CUDA cu121) + `requirements-train.txt` + клон piper-sample-generator |
| `config.yaml` | фраза, критерии, пути, параметры oww и наращивания по раундам |
| `_common.py` | сборка training-config openWakeWord из `config.yaml` (одно место для ключей драйвера) |
| `00_download_data.py` | **тяжёлое:** негативные фичи + RIR + шум (десятки ГБ, с докачкой) |
| `01_generate_positives.py` | стадия данных раунда: `--generate_clips --augment_clips` |
| `02_train.py` | стадия обучения раунда: `--train_model`, экспорт `айрис.onnx` |
| `03_evaluate.py` | честный end-to-end recall и ложные-в-час на held-out, выбор порога, `report.json` |
| `autoloop.py` | раунд = 01→02→03; не сошлось — растит позитивы/шаги/вес негативов + hard-negative mining |
| `04_export_install.py` | sha256, копия в `resources/models/wake/`, готовая запись каталога |

## Порядок запуска

```powershell
# 1. Окружение (крупно: CUDA torch ~2.5 ГБ + пакеты). Проверяет torch.cuda.
.\setup.ps1

# 2. Наборы данных (ДЕСЯТКИ ГБ, с докачкой). Отдельный шаг, не автозапуск обучения.
.\.venv\Scripts\Activate.ps1
python 00_download_data.py --config config.yaml

# 3. Held-out позитивы для оценки (один раз, чистые «Айрис» русским голосом).
python 00b_make_val_pos.py --config config.yaml

# 4. Автоцикл: генерация → обучение → оценка → повтор до критериев или лимита раундов.
#    PYTHONUTF8=1 обязателен: иначе train.py прочитает кириллицу конфига как cp1251.
$env:PYTHONUTF8=1; python autoloop.py --config config.yaml

# 5. Экспорт лучшего результата в репозиторий + готовая запись каталога.
python 04_export_install.py --onnx runs/round<N>/айрис.onnx --threshold <из report.json>
```

## Грабли окружения (проверено 2026-09-19 на этой машине)

Официальный тренинг-стек openWakeWord чувствителен к версиям — рабочая связка:

- **torch/torchaudio 2.5.1+cu121** с индекса PyTorch (CUDA:True на RTX 2060),
  openwakeword **0.6.0**, Python **3.11**.
- **piper-sample-generator — пин на коммит `4057c1a`** («Upgrade to torch 2,
  piper 1.3»). Его `generate_samples(text, output_dir, model=<en_US-libritts_r по
  умолчанию>, ...)` совпадает с вызовом из `openwakeword/train.py`. Более новые
  коммиты («Move to package») ломают ожидаемый `from generate_samples import
  generate_samples`. Зависимости piper ставить БЕЗ его `torch<2`/`numpy<2` из
  requirements — иначе снесут CUDA-сборку torch.
- **`scipy<1.15`** (стоит 1.14.1): тренинг-деп `acoustics` импортирует
  `scipy.special.sph_harm`, удалённый в scipy 1.15+ — иначе `import acoustics` и
  весь `openwakeword.train` не грузятся.
- **`webrtcvad-wheels`** вместо `webrtcvad`: у последнего нет колёс под Windows,
  сборка из исходников требует C-компилятора.
- Тренинг-деп, которые тянет `openwakeword.train`: `torchinfo torchmetrics
  speechbrain audiomentations torch-audiomentations acoustics mutagen pronouncing`.

Проверка, что драйвер жив: `python -m openwakeword.train --help` печатает флаги
`--generate_clips --augment_clips --overwrite --train_model`.

## Источники данных (те же, что в официальном ноутбуке openWakeWord)

- негативные фичи: `davidscripka/openwakeword_features` — `openwakeword_features_ACAV100M_2000_hrs_16bit.npy` и `validation_set_features.npy`;
- RIR: HF-датасет `davidscripka/MIT_environmental_impulse_responses`;
- фон/шум: `agkphysics/AudioSet` (tar `bal_train09.tar`) + `rudraml/fma` (small).

`00_download_data.py` тянет их с ретраями и докачкой (сеть нестабильна) и
откладывает held-out негативы (`data/val_neg`, ≥ `criteria.neg_eval_hours`), не
участвующие в аугментации.

## Русский голос — единственная адаптация под «Айрис» (важно)

Официальный `train.py` зовёт piper-sample-generator с его **английским** голосом
LibriTTS по умолчанию и не пробрасывает путь к голосу. Английский голос произнесёт
«айрис» с английской фонетикой — для русского слова это брак. Варианты:

1. Подменить дефолтный голос piper-sample-generator на **русский** (проект уже
   использует русские голоса Piper — `dmitri`, `irina`, `ruslan`, `denis`): скачать
   их `.onnx`+`.json` и указать генератору (см. его README, аргумент модели), либо
2. сгенерировать позитивы русскими голосами отдельно и подать openWakeWord готовые
   клипы, минуя его встроенный синтез.

Это единственное место, где англо-центричный официальный пайплайн требует правки
под русскую фразу. Проверять произношение — **на слух** по сэмплам из `data/`.

### Кодировка training-config (Windows, важно)

`openwakeword/train.py` читает свой `--training_config` через `open(path, 'r')`
**без `encoding=`** — на Windows дефолт локали (cp1251), а конфиг раунда пишется
UTF-8. Кириллица `айрис` тогда читается как мохибейк `Р°Р№СЂРёСЃ`, и espeak
фонемизирует его по буквам — все позитивы раунда синтезируются браком **молча**
(клипы есть, но «не по-русски»; папки раунда тоже с мохибейком в имени). Прямая
`PiperVoice.phonemize("айрис")` при этом верна — виновата именно кодировка чтения
yaml. Лечение: (1) патч site-packages — в `train.py` дописать `encoding='utf-8'`
в `open(args.training_config, ...)`; (2) запускать автоцикл с `PYTHONUTF8=1`
(env пробрасывается в подпроцессы стадий). Контроль первого раунда — по фонемам в
`autoloop.log`: должно быть `[ˈɑ j rʲ i s]`, а не `Р°Р№…`.

### Held-out позитивы (data/val_pos) не заполняются драйвером

`03_evaluate.py` мерит recall по `data/val_pos`, но официальный драйвер держит
свои валидационные позитивы внутри папки раунда и наружу не отдаёт, а `autoloop.py`
в `data/val_pos` ничего не кладёт. Пустой каталог → recall всегда 0 → цикл впустую
прокрутит все раунды. Поэтому held-out позитивы синтезируются отдельным
фиксированным набором **до** автоцикла: `python 00b_make_val_pos.py --config
config.yaml` (чистые «айрис» русским голосом, один раз).

## Held-out наборы

- **Негативы** (`data/val_neg`): откладывает `00_download_data.py` — ≥ 2 ч речи без
  слова, музыки и бытового шума, не использованные в обучении.
- **Позитивы** (`data/val_pos`): чёткие произнесения «Айрис», по одному на файл.
  Даёт первый раунд генерации (`n_samples_val` валидационных клипов) — скопировать
  их в `data/val_pos`, либо синтезировать отдельным набором русским голосом.

`03_evaluate.py` считает recall (макс. балл по файлу ≥ порога) и ложные-в-час
(срабатывания по скользящему окну ~1.5 c / шаг ~0.75 c, а не по файлу — иначе
метрика зависит от длины файлов).

## Критерии (мягкие, слово короткое)

- **recall ≥ 90 %** на чётких «Айрис»;
- **≤ 2 ложных/час** на held-out негативах (≥ 2 ч).

Порог, на котором это достигнуто, `03_evaluate.py` пишет в `report.json` — он
становится дефолтной чувствительностью варианта «айрис». Если строгие цифры
недостижимы — автоцикл упирается в `autoloop.max_rounds` и отдаёт лучший чекпойнт
с честным отчётом, а не крутится бесконечно.

## Интеграция с приложением

Приложение **не зависит** от наличия файла — только подхватывает его:

- Движок `openwakeword` при отсутствии файла поднимает штатную русскую ошибку на
  загрузке, а детектор её **не роняет наружу**: логирует, отдаёт в `on_error`,
  захват продолжается (`src/ayris/audio/wake_word/manager.py`, `WakeWordDetector.start`).
- Вариант ищется по имени файла-стема: фраза «айрис» → `айрис.onnx` в
  `wake_models_dir` (`openwakeword.py`, `_resolve`).

Когда `айрис.onnx` обучен и лежит рядом с общими частями
(`melspectrogram.onnx` + `embedding_model.onnx`), openWakeWord срабатывает на
«Айрис».

## Проверка живым голосом

Автометрики не заменяют живую проверку: реально ли ловит «Айрис» и молчит ли на
обычной болтовне — проверяется **руками** на профиле с тремя файлами
(мел-спектрограмма + эмбеддинги + `айрис.onnx`).
